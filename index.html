Introduction

JavaScript — The Language of the Web

From a first console.log to asynchronous iterators

JavaScript is the only programming language that every web browser understands. It began life in 1995 as a small scripting language for adding interactivity to web pages. Today it runs servers, mobile apps, desktop applications, and even robots. It is the most widely used programming language in the world — and one of the most misunderstood.

This book is a collection of notes from Stack Overflow Documentation, the community-written manual that grew out of Stack Overflow's Q&A. It is organised into one hundred and five chapters covering the language from its foundations to its most advanced features. The chapters are short and practical: each one focuses on a single topic, gives a code example you can run, and explains the idioms that professionals actually use.

The book is divided into eight parts. Part One covers the foundations: getting started, variables, constants, comments, the console, and datatypes. Part Two covers data types and control flow: strings, dates, comparisons, conditions, arrays, and objects. Part Three covers functions and object-oriented JavaScript: arithmetic, bitwise operators, constructors, declarations, loops, functions, functional JavaScript, prototypes, classes, namespacing, this, getters and setters, events, and inheritance.

Part Four covers patterns and asynchrony: method chaining, callbacks, timers, regular expressions, cookies, web storage, data attributes, JSON, AJAX, enumerations, Map, timestamps, unary operators, generators, Promises, and Set. Part Five covers the browser and web APIs. Part Six covers modern JavaScript. Part Seven covers advanced techniques. Part Eight covers professional practices — security, error handling, debugging, testing, linters, performance, and memory.

You do not need to read the book in order. Each chapter stands alone. But if you are new to JavaScript, start at the beginning and work your way forward. The language is strange at first — its type coercion will surprise you, its this will confuse you, its asynchrony will test your patience. But once it clicks, you will find that it is a remarkably expressive and flexible language.

Remember: the best way to learn a language is to write it. Every chapter ends with three exercises. Do them. Open your browser's console. Type the code. Break it. Fix it. That is how the language becomes yours.

Getting Started with JavaScript

Everything begins with a simple hello, world

All modern web browsers, Node.js, and almost every other JavaScript environment support writing messages to a console using a suite of logging methods. The most common of these is console.log(). Open your browser's JavaScript console, type console.log("Hello, World!"), and press Enter. The message appears — and the console returns undefined, because console.log() has no explicit return value.

You can log variables of any kind, not just strings. Pass the variable you want to display: var foo = "bar"; console.log(foo);. You can log multiple values by separating them with commas — spaces are automatically added between each argument. And you can use placeholders: console.log("%s, %s!", greet, who) prints Hello, World!.

But the console is only one way to interact with the page. The DOM API (Document Object Model) is an object-oriented representation of structured documents like XML and HTML. Setting the textContent property of an element is one way to output text: document.getElementById("paragraph").textContent = "Hello, World". You can also create elements programmatically: var element = document.createElement('p'); element.textContent = "Hello, World"; document.body.appendChild(element);.

For quick interactions, the browser provides three modal prompts. window.alert(message) displays a visual alert box. window.prompt(text, [default]) asks the user for input and returns a string (or null if cancelled). window.confirm(message) displays a dialog with OK and Cancel buttons and returns a boolean. These are useful for debugging, but they block the page — use them sparingly.

For graphical output, you can use <canvas> for raster images, SVG for vector graphics, or an image file loaded from a URL. Each approach has its strengths: canvas is fast for pixel manipulation, SVG is scalable and accessible, and images are simple and cacheable.

// The simplest hello, world
console.log("Hello, World!");

// Logging variables
var foo = "bar";
console.log(foo); // "bar"

// Placeholders
var greet = "Hello", who = "World";
console.log("%s, %s!", greet, who); // "Hello, World!"

// DOM manipulation
document.getElementById("paragraph").textContent = "Hello, World";

// Creating an element
var element = document.createElement('p');
element.textContent = "Hello, World";
document.body.appendChild(element);

// Modals
alert('hello, world');
var age = prompt("How old are you?");
if (window.confirm("Are you sure you want to delete this?")) {
  deleteItem(itemId);
}

Key Ideas

  • console.log() is the primary tool for debugging — it accepts any number of arguments and supports placeholders.
  • The DOM API lets you read and modify the page: select elements, set textContent, create new elements, and append them.
  • alert, prompt, and confirm are modal dialogs — useful for debugging but disruptive to the user experience.
  • For graphical output, choose canvas for pixels, SVG for vectors, or an image file for simplicity.

  1. Open the console and log three different values in a single console.log() call.
  2. Use prompt() to ask for a name and log a greeting with a placeholder.
  3. Create a <p> element with JavaScript and append it to the body.

JavaScript Variables

Containers for the values your program needs

Variables are what make up most of JavaScript. They hold numbers, strings, arrays, objects, functions — everything. A variable is declared with var, let, or const, followed by a name and optionally an assignment. var myVariable = "This is a variable!" creates a variable called myVariable and assigns it a string.

You can use a variable by referring to it by name. var number1 = 5; number1 = 3; — the first line defines the variable as 5, the second changes it to 3. To display the value, use console.log(number1) or window.alert(number1). You can perform arithmetic: number1 = number1 + 5;, number1 = number1 - 6;, and so on. Strings can be concatenated with the + operator: "I am a " + "string!".

JavaScript has several built-in types. Numbers are 64-bit floating point; there is no separate integer type. Booleans are true and false. Strings are sequences of Unicode characters. NaN means "Not a Number"; undefined means a variable has been declared but not assigned; null means an intentional absence of value. Arrays are ordered collections: var favoriteFruits = ["apple", "orange", "strawberry"];. Objects are key-value collections: var john = {firstname: "John", lastname: "Doe", fullname: "John Doe"};.

JavaScript has dynamic types. The same variable can hold a number, then a string, then an object. This flexibility is powerful, but it also means you need to be careful about type coercion. The language will try to convert values to more appropriate types when you use them — sometimes with surprising results.

// Declaration and assignment
var myVariable = "This is a variable!";

// Numbers
var myInteger = 12;       // 32-bit number
var myFloat = 5.5;        // 32-bit float
var myDouble = 9310141419482.22; // 64-bit float

// Booleans
var myBoolean = true;
var myBoolean2 = false;

// Special values
var myNotANumber = NaN;
var notDefined;           // undefined
var myNull = null;        // null

// Arrays
var favoriteFruits = ["apple", "orange", "strawberry"];
window.alert(favoriteFruits[0]); // "apple"

// Objects
var john = {firstname: "John", lastname: "Doe", fullname: "John Doe"};
window.alert(john.fullname); // "John Doe"

Key Ideas

  • Variables are declared with var, let, or const and can hold any type.
  • JavaScript has dynamic types: the same variable can hold different types at different times.
  • Arrays are indexed collections; objects are key-value collections.
  • Special values include NaN, undefined, and null — each has a precise meaning.

Built-in Constants

null, undefined, NaN, and Infinity — the values that aren't values

null represents the intentional absence of an object value. It is a primitive value, and unlike undefined, it is not a property of the global object. It is equal to undefined with == but not with ===. Careful: typeof null is 'object' — a long-standing quirk of the language. To check for null, compare with the strict equality operator: a === null.

NaN stands for "Not a Number." When a mathematical function or operation cannot return a specific number, it returns NaN instead. It is a property of the global object, and a reference to Number.NaN. Confusingly, typeof NaN is 'number'. And NaN == NaN is false — NaN is not equal to itself. To test for NaN, use Number.isNaN() (strict, ES6) or the older isNaN() (which coerces its argument).

undefined is the absence of an assigned value. It is a global value; typeof undefined === 'undefined'. A variable declared but not assigned is undefined. A function that returns nothing returns undefined. A missing function argument is undefined. Accessing a non-existent property returns undefined.

Infinity is a property of the global object that represents mathematical infinity. You can get it by dividing by zero, or by evaluating an expression that overflows. 1/0 === Infinity. There is also -Infinity, which is lower than any other value. 23 / Infinity === 0. And interestingly, Infinity === Number.POSITIVE_INFINITY and -Infinity === Number.NEGATIVE_INFINITY.

The Number constructor also has useful constants: Number.MAX_VALUE, Number.MIN_VALUE, Number.MAX_SAFE_INTEGER, Number.MIN_SAFE_INTEGER, Number.EPSILON, Number.POSITIVE_INFINITY, Number.NEGATIVE_INFINITY, and Number.NaN. Operations that return NaN include arithmetic on non-numbers ("b" * 3), 0/0, and Math.sqrt(-1).

// null vs undefined
null == undefined;  // true
null === undefined; // false
typeof null;        // 'object'

// NaN
typeof NaN;         // 'number'
NaN === NaN;        // false
Number.isNaN(NaN);  // true
Number.isNaN("24"); // false (it's not a number, but not NaN)
isNaN("24");        // false (coerces "24" to 24)

// Infinity
1 / 0;              // Infinity
-Infinity < -1e308; // true
23 / Infinity;      // 0

// Number constants
Number.MAX_SAFE_INTEGER; // 9007199254740991
Number.EPSILON;          // 0.0000000000000002220446049250313

Key Ideas

  • null is intentional absence; undefined is an unassigned value. They are loosely equal but not identical.
  • NaN is a number that isn't equal to itself — use Number.isNaN() to test for it.
  • Infinity and -Infinity are real values; division by zero produces Infinity, not an error.
  • Number.MAX_SAFE_INTEGER and Number.EPSILON define the boundaries of reliable numeric operations.

Comments

Annotations, hints, and the occasional excluded line

JavaScript provides two ways of commenting code lines. The single-line comment starts with //. Everything after the // until the end of the line is excluded from execution. Use it to annotate a line, explain an intent, or add a TODO. function elementAt(event) { // Gets the element from Event coordinates return document.elementFromPoint(event.clientX, event.clientY); } // TODO: write more cool stuff!

The multi-line comment starts with /* and ends with */. Everything between them is excluded from execution, even across lines. Use it to temporarily disable a block of code, or to write a longer explanation. /* Gets the element from Event coordinates. Use like: var clickedEl = someEl.addEventListener("click", elementAt, false); */ function elementAt(event) { return document.elementFromPoint(event.clientX, event.clientY); }

There is also a third, historical form: the HTML comment. In legacy JavaScript, <!-- was used to hide JavaScript from browsers that didn't support it. Modern browsers still accept it as a one-line comment, but it is considered bad practice and should be avoided.

Good comments explain why, not what. The code should be self-explanatory; comments should add context that the code cannot express. Avoid commenting out code — your source control system remembers it. Avoid redundant comments like i++; // increment i. Avoid outdated comments that lie about what the code does.

// Single-line comment
function elementAt(event) {
  // Gets the element from Event coordinates
  return document.elementFromPoint(event.clientX, event.clientY);
}

// TODO: write more cool stuff!

/* Multi-line comment
   Use like:
   var clickedEl = someEl.addEventListener("click", elementAt, false);
*/
function elementAt(event) {
  return document.elementFromPoint(event.clientX, event.clientY);
}

/* TODO: write more useful comments! */

Key Ideas

  • Use // for single-line comments and /* ... */ for multi-line comments.
  • Good comments explain why, not what — the code should say what it does.
  • Avoid HTML comments in modern JavaScript — they are legacy and bad practice.
  • Don't comment out code; delete it — source control remembers it.

  1. Add a single-line comment explaining a tricky line in your code.
  2. Replace a multi-line block comment with a single-line comment if one line will do.
  3. Delete a block of commented-out code — your source control system still remembers it.

Console

The developer's window into the running program

The console object gives you a suite of methods for writing messages, measuring time, tabulating data, and debugging. In most browsers, the console is integrated into Developer Tools. Open it with Ctrl+Shift+J (Windows/Linux Chrome), Cmd+Opt+J (Mac Chrome), Ctrl+Shift+K (Firefox), or F12 (Edge/IE). In Safari, enable the Develop menu in Preferences first.

console.log() is the most familiar method, but the console has many more. console.info, console.warn, and console.error display messages with different icons and background colors. console.time(label) and console.timeEnd(label) measure elapsed time. console.table() displays arrays and objects in a tabular format. console.count() counts how many times it has been called. console.assert(condition, message) logs an error if the condition is false. console.trace() prints a stack trace. console.group() and console.groupEnd() create collapsible groups.

Console output can be formatted with C-like tokens: %s for strings, %d or %i for integers, %f for floats, %o for expandable objects, and %c for CSS styling. console.log('%cHello world!', 'color: blue; font-size: xx-large') prints a styled message.

Some older environments (IE8 and below) only define console when Developer Tools are open. To be safe, wrap your logging: if (typeof window.console !== 'undefined') { console.log("Hello World"); }.

console.log('My message');
console.info('Information');
console.warn('Warning');
console.error('Error');

console.time('loop');
for (let i = 0; i < 5000; i++) { /* ... */ }
console.timeEnd('loop'); // loop: 40.716ms

console.table({foo: 'bar', bar: 'baz'});

console.count('hit'); // hit: 1
console.count('hit'); // hit: 2

console.assert('one' === 1, 'one is not 1');
// Assertion failed: one is not 1

console.group('My group');
console.log('inside');
console.groupEnd();

console.log('%cHello world!', 'color: blue; font-size: xx-large');
console.log('%s has %d points', 'Sam', 100); // Sam has 100 points

Key Ideas

  • The console has many methods beyond log: info, warn, error, time, table, count, assert, trace, group.
  • Use console.time() and console.timeEnd() to measure performance.
  • Format console output with %s, %d, %f, %o, and %c tokens.
  • Guard against console being undefined in old browsers.

  1. Open your browser's console and try console.table() with an array of objects.
  2. Measure how long a loop takes with console.time() and console.timeEnd().
  3. Use %c to print a styled message to the console.

Datatypes in JavaScript

typeof tells you what you're looking at — most of the time

JavaScript has six primitive types — string, number, boolean, null, undefined, and symbol — plus object and function. The typeof operator returns a string telling you which type a value has. typeof "String" returns "string". typeof 42 returns "number". typeof true returns "boolean". typeof {}, typeof [], typeof null, and typeof /aaa/ all return "object". typeof function(){} returns "function". And typeof undefined returns "undefined".

Notice the problem: typeof cannot distinguish an array from an object from null. That's why Array.isArray() exists. And typeof null === 'object' is a long-standing bug in the language — to check for null, compare with === null.

To find whether an object was constructed by a certain constructor or one inheriting from it, use instanceof. But note: primitive values are not instances of any class. 2 instanceof Number is false. 'abc' instanceof String is false. Every value except null and undefined also has a constructor property — but this is not always reliable either.

The most robust way to find an object's class is Object.prototype.toString.call(yourObject). It returns "[object String]", "[object Number]", "[object Boolean]", "[object Object]", "[object Function]", "[object Date]", "[object RegExp]", "[object Array]", "[object Null]", "[object Undefined]", or "[object Error]".

typeof "String"        // "string"
typeof 42              // "number"
typeof true            // "boolean"
typeof {}              // "object"
typeof []              // "object"
typeof null            // "object" (the famous bug)
typeof /aaa/           // "object"
typeof function(){}    // "function"
typeof undefined       // "undefined"

// instanceof
2 instanceof Number    // false (primitives are not instances)
[] instanceof Object   // true
[] instanceof Array    // true

// Object.prototype.toString
Object.prototype.toString.call("String")  // "[object String]"
Object.prototype.toString.call(42)        // "[object Number]"
Object.prototype.toString.call([])        // "[object Array]"
Object.prototype.toString.call(null)      // "[object Null]"
Object.prototype.toString.call(undefined) // "[object Undefined]"
Object.prototype.toString.call(new Date)  // "[object Date]"

Key Ideas

  • typeof returns the primitive type name — but typeof null is "object", and arrays are also "object".
  • instanceof checks the prototype chain — but only works for objects, not primitives.
  • Object.prototype.toString.call(x) gives the most precise class name.
  • Array.isArray() is the reliable way to check for arrays.

Strings

Sequences of Unicode characters, and the methods that manipulate them

Strings in JavaScript can be enclosed in single quotes 'hello', double quotes "Hello", or template literals `hello` (from ES2015). Strings can be created from other types using String() or .toString(). String(32) returns "32"; (5232).toString() returns "5232". String.fromCharCode(104,101,108,108,111) returns "hello".

Concatenation uses the + operator or the concat() method. "Foo" + "Bar" is "FooBar". When you concatenate a string with a number, the number is converted to a string: "string" + 32 + true is "string32true". Template literals support interpolation: `Hello ${place}!`.

Strings are immutable: methods like charAt(), slice(), indexOf(), replace(), toUpperCase(), and toLowerCase() return new strings rather than modifying the original. str.split('') splits into an array of characters; arr.join('') joins them back. This is the basis of the classic string-reversal idiom: str.split('').reverse().join('').

Strings are Unicode. JavaScript has no raw byte or binary strings; for binary data, use Typed Arrays. To detect a string, use typeof value === 'string' (primitive) or value instanceof String (object). The String() constructor creates a String object — but this is rarely what you want; use primitive strings.

Other useful methods: .trim() removes whitespace from both ends; .includes() checks for a substring; .startsWith() and .endsWith() check prefixes and suffixes; .repeat(n) repeats a string n times; .charCodeAt(i) returns the Unicode code point of the character at index i; .codePointAt(i) handles code points beyond 2¹⁶ − 1.

var hello = "Hello";
var world = 'world';
var helloW = `Hello World`; // ES2015

// Concatenation
console.log(hello + " " + world); // "Hello world"
console.log(hello.concat(" ", world)); // "Hello world"

// Template literals
var place = 'World';
var greet = `Hello ${place}!`;
console.log(greet); // "Hello World!"

// Common methods
"some whitespace string".trim();        // "some whitespace string"
"one, two, three".split(", ");          // ["one", "two", "three"]
"string".includes("ing");               // true
"abc".repeat(3);                        // "abcabcabc"
"Hello World".indexOf("World");         // 6
"Hello World".toUpperCase();            // "HELLO WORLD"
"QWERTY".toLowerCase();                 // "qwerty"

// Reversing a string
function reverseString(str) {
  return str.split('').reverse().join('');
}
reverseString('string'); // "gnirts"

Key Ideas

  • Strings are immutable — methods return new strings, not modify the original.
  • Template literals support interpolation with ${...} and multi-line strings.
  • Use split('') and join('') to convert between strings and arrays of characters.
  • Strings are Unicode; for binary data, use Typed Arrays.

Date

A moment in time, represented as milliseconds since the Unix epoch

The Date constructor creates a new Date object. With no arguments, it gives the current time. With one integer argument, it treats the argument as milliseconds since 1 January 1970 UTC. With a string argument, it parses the string. With two or more integers, it treats them as year, month (0-indexed), day, hours, minutes, seconds, milliseconds — in local time. Use Date.UTC() to create a date from UTC components.

JavaScript dates are mutable objects. You can change them with methods like setDate(), setFullYear(), setHours(), and so on. There are UTC equivalents: setUTCDate(), setUTCFullYear(), and so on. To get the number of milliseconds since the epoch, use Date.now() (static) or date.getTime() (instance).

Formatting methods include toString(), toTimeString(), toDateString(), toUTCString(), toISOString(), toLocaleDateString(), and toLocaleTimeString(). For modern formatting, use Intl.DateTimeFormat. toJSON() returns an ISO string — useful for serialization.

Be careful with timezones. A date created without Date.UTC is in local time. When communicating between server and client in different timezones, use UTC dates throughout, and only convert to local time when displaying. The getTimezoneOffset() method returns the difference in minutes between UTC and local time.

// Current time
var now = new Date();

// From milliseconds since epoch
var epoch = new Date(0); // 1970-01-01T00:00:00.000Z

// From components (local time; month is 0-indexed)
var date = new Date(2017, 5, 1); // June 1, 2017

// From UTC components
var utc = new Date(Date.UTC(2012, 0)); // 2012-01-01T00:00:00.000Z

// Formatting
var date1 = new Date();
date1.toISOString();       // "2016-04-14T23:49:08.596Z"
date1.toUTCString();       // "Fri, 15 Apr 2016 11:48:48 GMT"
date1.toLocaleDateString(); // "4/14/2016"

// Milliseconds since epoch
Date.now();
(new Date()).getTime();

// Increment a date by one day
var checkoutDate = new Date();
checkoutDate.setDate(checkoutDate.getDate() + 1);

// Convert to JSON
new Date().toJSON(); // "2016-04-14T23:49:08.596Z"

Key Ideas

  • new Date() gives current time; new Date(ms) gives epoch + ms; new Date(y, m, d, ...) gives local time.
  • Months are 0-indexed: 0 is January, 11 is December.
  • Use Date.UTC() when creating dates from UTC components.
  • Use getTime() or Date.now() for milliseconds since the epoch.

Date Comparison

Compare moments, not object references

To check the equality of two Date objects, you cannot use === — that compares object references, not values. Two dates that represent the same moment but are different objects will not be equal with ===. Use valueOf() or getTime() to compare the underlying timestamps: date1.valueOf() === date2.valueOf().

The other comparison operators — <, >, <=, >= — work as expected because the Date object is implicitly converted to a number by the comparison. date1 < date2 is true if date1 is earlier.

To calculate the difference between two dates, subtract their timestamps. The result is in milliseconds; divide to convert to seconds, minutes, hours, days, or years. dateDiff / 1000 / 60 / 60 / 24 / 365 gives years.

var date1 = new Date();
var date2 = new Date(date1.valueOf() + 10);

// Equality: use valueOf() or getTime()
console.log(date1.valueOf() === date2.valueOf()); // false

// Object reference equality: generally false
console.log(new Date() === new Date()); // false

// Relational operators work as usual
console.log(date1 < date2);  // true
console.log(date1 <= date2); // true

// Difference in milliseconds
var dateDiff = date2.valueOf() - date1.valueOf();
console.log(dateDiff); // 10

// Difference in years
var dateDiffInYears = dateDiff / 1000 / 60 / 60 / 24 / 365;
console.log("Date difference in years: " + dateDiffInYears);

Key Ideas

  • Use valueOf() or getTime() for date equality — === compares object references.
  • Use <, >, <=, >= for relational comparisons — they convert dates to timestamps.
  • Subtract timestamps to get date differences; divide by the appropriate units.

Comparison Operations

== vs ===, truthiness, short-circuiting, and the strange corners of type coercion

JavaScript has four equality comparison operations: SameValue (Object.is), SameValueZero (Array.prototype.includes), Strict Equality (===), and Abstract Equality (==). The strict equality operator compares both value and type — no coercion. The abstract equality operator coerces its operands to a common type before comparing. The result is that "0" == 0 is true, but "0" === 0 is false.

The abstract equality algorithm is complex. If the operands are the same type, it behaves like ===. If one is null and the other undefined, it returns true. If a number is compared with a string, the string is coerced to a number. If a boolean is compared with anything, the boolean is coerced to a number. If an object is compared with a number, string, or symbol, the object is coerced to a primitive. Each coercion can produce surprising results. 1 == true is true; 0 == false is true; "" == 0 is true; [] == false is true.

NaN is never equal to anything, including itself. NaN == NaN is false; NaN === NaN is false. To test for NaN, use Number.isNaN(value) or the self-comparison trick value !== value.

Logical operators && and || short-circuit: the right operand is not evaluated if the left operand determines the result. This is often used to provide default values (value || defaultValue) or conditional execution (condition && action()). The logical NOT operator ! coerces its operand to boolean and negates it. The double negation !! is a common idiom for explicit boolean conversion.

// Abstract equality coerces
1 == "1";         // true
1 === "1";        // false
null == undefined; // true
null === undefined; // false
0 == false;       // true
"" == 0;          // true
[] == false;      // true

// NaN
NaN == NaN;       // false
Number.isNaN(NaN); // true

// Short-circuiting
var x = null;
var y = x || "default"; // "default"
x && x.property;        // null (no error)

// Double negation
!!"hello"  // true
!!0        // false
!![]       // true

// Relational operators
1 < 2          // true
"a" < "b"      // true
1 < "abc"      // false (NaN comparison)
1 > ""         // true ("" coerces to 0)

Key Ideas

  • === compares value and type; == coerces. Prefer === to avoid surprises.
  • NaN is not equal to itself — use Number.isNaN().
  • Use || to provide default values and && for conditional execution.
  • !!value converts to boolean; truthy values include non-empty strings, non-zero numbers, objects, arrays.

Conditions

if, else, switch, ternary — and the strategy pattern

The if statement evaluates a condition and executes a block if the condition is truthy. An optional else block executes if the condition is falsy. The condition can be any expression that can be coerced to a boolean: numbers, strings, objects, comparisons. Empty strings, 0, NaN, null, undefined, and false are falsy; everything else is truthy.

For multiple branches, use else if. The first true condition is the only one executed. The if-else-if ladder exits at the first success. Braces around single statements are technically optional but strongly recommended — without them, a misleading indentation can introduce bugs.

The ternary operator (condition ? valueIfTrue : valueIfFalse) is a concise alternative to if/else for simple assignments. It always expects both branches. Ternaries can be nested, but for readability, keep them short. The switch statement compares an expression against multiple cases. Without a break or return, execution "falls through" to the next case — which can be useful for grouping cases, but is also a common source of bugs. The default case handles values not matched by any case.

For large or dynamic sets of conditions, consider the strategy pattern: an object whose properties are functions, indexed by the condition. AnimalSays[animal] || AnimalSays.default selects the right behaviour without a long switch. Short-circuiting with || and && can also simplify simple conditional logic: x === 10 && alert("x is 10").

// if / else if / else
var i = 0;
if (i < 1) {
  console.log("i is smaller than 1");
} else if (i < 2) {
  console.log("i is smaller than 2");
} else {
  console.log("none of the previous conditions was true");
}

// Ternary
var animal = 'kitty';
var result = (animal == 'kitty') ? 'cute' : 'still nice';

// Switch
var value = 1;
switch (value) {
  case 1:
    console.log('I will always run');
    break;
  case 2:
    console.log('I will never run');
    break;
  default:
    console.log('Default case');
}

// Strategy pattern
const AnimalSays = {
  dog() { return 'woof'; },
  cat() { return 'meow'; },
  lion() { return 'roar'; },
  default() { return 'moo'; }
};
function makeAnimalSpeak(animal) {
  const speak = AnimalSays[animal] || AnimalSays.default;
  console.log(animal + ' says ' + speak());
}

Key Ideas

  • if/else if/else handles multiple branches; the first true condition wins.
  • The ternary operator is concise but should be used only for simple conditions.
  • switch needs break or return to prevent fall-through.
  • The strategy pattern replaces long switch statements with an object of functions.

Arrays

Ordered collections with a rich toolkit of methods

Arrays are ordered collections of values. You can create them with array literals or the Array constructor: var arr = [1, 2, 3, 4]; or var arr2 = new Array(1, 2, 3, 4);. The constructor with a single numeric argument creates an array of that length with all undefined values; use Array.of() instead if you mean to create an array with a single value. Array.from() converts array-like objects into arrays.

Arrays inherit from Array.prototype, which provides a rich set of methods. .map() transforms each element. .filter() keeps only elements that pass a test. .reduce() condenses the array to a single value. .forEach() iterates without returning. .sort() sorts in place (and needs a comparator for numbers). .reverse() reverses in place. .slice() returns a shallow copy of part of the array. .splice() removes or adds elements in place. .concat() joins arrays. .join() creates a string from the elements. .find() and .findIndex() search. .some() and .every() test. .flat() flattens nested arrays.

You can iterate arrays with traditional for loops, for...of loops (which iterate values), for...in loops (which iterate indices — avoid), and .forEach(). ES6 destructuring lets you unpack arrays: const [a, b] = [1, 2];. The spread operator ... expands arrays into individual elements. The rest operator ... collects individual elements into an array.

To remove duplicates, use [...new Set(array)] or filter with indexOf. To find the maximum or minimum, use Math.max(...array) or array.reduce(). To compare two arrays, use JSON.stringify or a recursive comparison. To test if a value is an array, use Array.isArray().

var numbers = [5, 32, 43, 4];

// map
var doubled = numbers.map(n => n * 2); // [10, 64, 86, 8]

// filter
var odd = numbers.filter(n => n % 2 !== 0); // [5, 43]

// reduce
var sum = numbers.reduce((a, b) => a + b); // 84

// sort (numeric)
numbers.sort((a, b) => a - b); // [4, 5, 32, 43]

// reverse (in place)
[1, 2, 3].reverse(); // [3, 2, 1]

// slice (new array)
["a", "b", "c", "d"].slice(1, 3); // ["b", "c"]

// splice (in place)
var arr = [1, 2, 3, 4];
arr.splice(1, 2); // returns [2, 3]; arr is now [1, 4]

// concat
[1, 2].concat([3, 4]); // [1, 2, 3, 4]

// join
["Hello", " ", "world"].join(""); // "Hello world"

// spread
var arr1 = [1, 2];
var arr2 = [3, 4];
var combined = [...arr1, ...arr2]; // [1, 2, 3, 4]

// destructuring
const [first, second, ...rest] = [1, 2, 3, 4];
// first === 1, second === 2, rest === [3, 4]

// remove duplicates
var unique = [...new Set([1, 2, 1, 3, 2])]; // [1, 2, 3]

// max
Math.max(...numbers); // 43

Key Ideas

  • Arrays have powerful methods: map, filter, reduce, sort, slice, splice, concat, find.
  • Some methods mutate in place (sort, reverse, splice); others return new arrays (map, filter, slice).
  • Use [...new Set(array)] to remove duplicates.
  • Use the spread operator to expand arrays, the rest operator to collect elements into an array.

Objects

Key-value collections, property descriptors, and the building blocks of everything

Objects are key-value collections. Create them with object literals: var obj = {a: 1, b: 2};. Access properties with dot notation (obj.a) or bracket notation (obj['a']). Bracket notation is required for property names that are not valid identifiers, like "my-key". You can add properties dynamically: obj.c = 3;.

To clone an object shallowly, use Object.assign({}, obj) or the spread operator {...obj}. For a deep clone, JSON.parse(JSON.stringify(obj)) works for JSON-serializable objects. Object.freeze(obj) makes an object immutable (shallowly). Object.seal(obj) prevents adding or removing properties but allows editing existing ones. Object.defineProperty(obj, 'name', descriptor) gives fine-grained control over a property's behaviour — its value, writability, enumerability, and configurability. Getter and setter functions can be defined with get and set in a descriptor or object literal.

To iterate over an object's properties, use for...in (with a hasOwnProperty check), Object.keys(obj), Object.values(obj), or Object.entries(obj). To check if a property exists, use obj.hasOwnProperty('key') or the in operator. To convert an object to an array of key-value pairs, use Object.entries().

Objects can be frozen, sealed, or made non-extensible. Object.getOwnPropertyDescriptor() returns the descriptor of a property. Object.getOwnPropertyNames() returns all own property names, including non-enumerable ones. Object.getOwnPropertySymbols() returns own symbol properties. Understanding property descriptors is key to understanding the language itself — they underpin prototypes, classes, and modules.

// Object literal
var obj = {a: 1, b: 2, c: 3};

// Shallow clone
const clone = Object.assign({}, obj);
const clone2 = {...obj};

// Deep clone (JSON-serializable)
const deepClone = JSON.parse(JSON.stringify({a: {b: 1}}));

// Object.freeze

Object.freeze(frozen);
frozen.foo = 'bar'; // silently fails (or throws in strict mode)

// Object.defineProperty

person.fullName = "Mary Jones";
console.log(person.name); // "Mary"

// Iteration
Object.keys(obj);    // ["a", "b", "c"]
Object.values(obj);  // [1, 2, 3]
Object.entries(obj); // [["a", 1], ["b", 2], ["c", 3]]

  if (obj.hasOwnProperty(prop)) {
    console.log(prop, obj[prop]);
  }
}

// Property descriptor

// {value: "world", writable: true, enumerable: true, configurable: true}

  • Objects are key-value collections; access properties with dot or bracket notation.
  • Object.assign and the spread operator create shallow clones; use JSON for deep clones.
  • Object.freeze, Object.seal, and Object.defineProperty control an object's mutability and property behaviour.

Arithmetic (Math)

Numbers, rounding, random values, trigonometry, and the Math object

The Math object provides constants and functions for mathematical operations. Constants include Math.E, Math.LN2, Math.LN10, Math.LOG2E, Math.LOG10E, Math.PI, Math.SQRT1_2, and Math.SQRT2. The Number constructor also has constants: Number.EPSILON, Number.MAX_SAFE_INTEGER, Number.MAX_VALUE, Number.MIN_SAFE_INTEGER, Number.MIN_VALUE, Number.POSITIVE_INFINITY, and Number.NEGATIVE_INFINITY.

The remainder operator % returns the remainder after division. 42 % 10 is 2. It is often used to test divisibility and to implement cyclic behaviour. Note that the sign of the result follows the sign of the dividend: -42 % 10 is -2.

Rounding functions: Math.round() rounds to the nearest integer (half up). Math.ceil() rounds up. Math.floor() rounds down. Math.trunc() removes the decimal part. To round to a specific number of decimal places, multiply by a power of ten, round, and divide: Math.round(num * 100) / 100.

For random numbers, Math.random() returns a float in [0, 1). To get an integer in a range, use Math.floor(Math.random() * (max - min + 1)) + min. Math.max() and Math.min() return the largest and smallest of their arguments; use the spread operator to apply them to an array: Math.max(...array).

Other useful functions: Math.pow() (or the ** operator) for exponentiation, Math.sqrt() for square root, Math.cbrt() for cube root, Math.hypot() for the square root of the sum of squares, and the trigonometric functions Math.sin, Math.cos, Math.tan, Math.asin, Math.acos, Math.atan, and Math.atan2.

Bitwise Operators

Operations on the 32-bit binary representation of numbers

Bitwise operators perform operations on the bits of their operands. Before the operation, both operands are converted to signed 32-bit integers in two's complement format. Numbers with more than 32 bits discard their most significant bits. JavaScript uses Big Endian to store integers; when using typed arrays with bit lengths greater than 8 bits, check the endianness of the environment.

The operators are: & (AND), | (OR), ^ (XOR), ~ (NOT), << (left shift), >> (sign-propagating right shift), and >>> (zero-fill right shift). Each can also be combined with assignment: &=, |=, ^=, <<=, >>=, >>>=.

Bitwise operators are fast because they work directly on the binary representation. They are useful for flags, parity checks, and low-level data manipulation. n & 1 is a fast parity check: it returns 1 for odd numbers, 0 for even. ~ can be used with indexOf to simplify existence checks: if (~array.indexOf(item)) is true if the item exists. a ^ b can swap two variables without an extra temporary variable: a = a ^ b; b = a ^ b; a = a ^ b;.

But beware: bitwise operators are not the same as logical operators. & and | are bitwise; && and || are logical. Using the wrong one can cause silent bugs. And ~ is not the power operator (that's **).

13 & 7;   // 5
13 | 7;   // 15
13 ^ 7;   // 10
~13;      // -14
5 << 2;   // 20 (multiply by 2^2)
20 >> 2;  // 5 (divide by 2^2)
-30 >>> 2; // 1073741816 (zero-fill right shift)

// Parity check
if (n & 1) {
  console.log("ODD!");
} else {
  console.log("EVEN!");
}

// Swap two integers with XOR
var a = 11, b = 22;
a = a ^ b;
b = a ^ b;
a = a ^ b;
console.log("a = " + a + "; b = " + b); // a = 22; b = 11

// ~ shorthand for indexOf
if (~items.indexOf('a')) {
  // item exists
}

Key Ideas

  • Bitwise operators work on 32-bit signed integers in two's complement.
  • &, |, ^, ~, <<, >>, >>> are the bitwise operators.
  • Use n & 1 for fast parity checks.
  • Use ~array.indexOf(item) as a shorthand for existence checks.

Constructor Functions

The pre-class way to create objects with shared behaviour

Constructor functions are functions designed to construct a new object. Within a constructor function, the keyword this refers to a newly created object, to which values can be assigned. Constructor functions "return" this new object automatically. function Cat(name) { this.name = name; this.sound = "Meow"; } defines a constructor. Invoke it with new: let cat = new Cat("Tom");.

Constructor functions have a prototype property, which points to an object whose properties are automatically inherited by all objects created with that constructor. Cat.prototype.speak = function() { console.log(this.sound); }; — then cat.speak() outputs "Meow".

Objects created by constructor functions also have a special property on their prototype called constructor, which points to the function used to create them. cat.constructor === Cat is true. And cat instanceof Cat is also true. This is the basis of the prototype chain.

Constructor functions are the pre-ES6 way of defining classes. Since ES6, the class syntax is preferred for new code, but constructor functions still work and are widely used in older codebases.

function Cat(name) {
  this.name = name;
  this.sound = "Meow";
}

let cat = new Cat("Tom");
cat.sound; // "Meow"

Cat.prototype.speak = function() {
  console.log(this.sound);
};

cat.speak(); // "Meow"
cat.constructor === Cat; // true
cat instanceof Cat;      // true

// A more complete example
function Person(name, age) {
  this.name = name;
  this.age = age;
}
Person.prototype.greet = function() {
  return "Hello, I'm " + this.name;
};

var alice = new Person("Alice", 30);
alice.greet(); // "Hello, I'm Alice"

Key Ideas

  • Constructor functions use this to assign properties to a new object, and are invoked with new.
  • Methods should be added to the constructor's prototype so they are shared across instances.
  • instanceof checks whether an object was created by a given constructor (or one of its ancestors).

Constants and Declarations

var, let, const — scope, hoisting, and reassignment

JavaScript has four ways to declare a variable: var, let, const, and bare declaration (without a keyword). The method you choose determines the variable's scope and whether it can be reassigned. var creates a function-scoped variable. let and const create block-scoped variables. A bare declaration creates a global variable — but this is discouraged and fails in strict mode.

const creates a block-scoped variable whose binding cannot be reassigned — but the value it holds can still be mutated if it's an object. const person = {name: "John"}; — person.name = "Steve" is allowed; person = {} is not. You must initialize a const at the point of declaration; const foo; throws a SyntaxError.

Variables declared with var are hoisted to the top of their function scope, and automatically initialized to undefined. Variables declared with let and const are also hoisted, but are in a "temporal dead zone" — accessing them before declaration throws a ReferenceError. Assigning a value to an undeclared variable in non-strict mode automatically creates a global — in strict mode, it throws a ReferenceError.

JavaScript has dynamic types: the same variable can hold different types at different times. var a; is undefined; a = 5 makes it a number; a = "John" makes it a string. The declaration keywords determine scope and reassignment, not the type.

// var: function-scoped, reassignable
var a = 'foo';
if (true) {
  var a = 'bar';
}
console.log(a); // "bar"

// let: block-scoped, reassignable
let b = 'foo';
if (true) {
  let b = 'bar';
  console.log(b); // "bar"
}
console.log(b); // "foo"

// const: block-scoped, not reassignable
const c = 'foo';
// c = 'bar'; // TypeError

// const objects can be mutated
const person = {name: "John"};
person.name = "Steve"; // allowed
person.surname = "Fox"; // allowed

// Hoisting
console.log(d); // undefined (var hoisting)
var d = 42;

// console.log(e); // ReferenceError (let/const TDZ)
let e = 42;

// Assignment operators
var x = 9, y = 3;
y += x; // y is now 12
y -= x; // y is now 3
y *= x; // y is now 27
y /= x; // y is now 3
y **= x; // y is now 19683 (ES2016)

Key Ideas

  • var is function-scoped; let and const are block-scoped.
  • const prevents reassignment but not mutation of objects.
  • Variables declared with var are hoisted and initialized to undefined; let/const are hoisted but in a temporal dead zone.
  • Prefer const for values that don't change, let for values that do, and avoid var in new code.

Loops

for, for...of, for...in, while, do...while — and when to use each

The traditional for loop has three components: initialization, condition, and afterthought, separated by semicolons. for (var i = 0; i < 100; i++) { console.log(i); } is the most common form. All three components are optional; for (;;) { } is valid — but you'll need a break inside to stop it. The for loop can iterate through arrays, use multiple declarations, or decrement.

The for...of loop (ES6) iterates over the values of an iterable: arrays, strings, sets, maps. for (let value of array) { console.log(value); }. It supports break, continue, and return — unlike forEach. The for...in loop iterates over the enumerable property names of an object (including inherited ones). It is intended for objects, not arrays — use it with a hasOwnProperty check.

The while loop executes as long as a condition is true: while (i < 100) { console.log(i); i++; }. The do...while loop always executes at least once, because the condition is checked at the end: do { console.log(i); } while (i < 100);.

break exits the innermost loop. continue skips to the next iteration. Both can be labelled to target a specific loop: outerloop: for (...) { innerloop: for (...) { if (j == 1) break outerloop; } }. Labelled statements are powerful but can make code harder to follow — use them sparingly.

// Traditional for loop
for (var i = 0; i < 100; i++) {
  console.log(i);
}

// for...of (ES6) — iterates values
const iterable = [0, 1, 2];
for (let i of iterable) {
  console.log(i);
}

// for...in — iterates keys
var object = {"a": "foo", "b": "bar"};
for (var key in object) {
  if (object.hasOwnProperty(key)) {
    console.log(key, object[key]);
  }
}

// while loop
var i = 0;
while (i < 100) {
  console.log(i);
  i++;
}

// do...while loop
var j = 101;
do {
  console.log(j);
} while (j < 100); // runs once

// break and continue
for (var k = 0; k < 3; k++) {
  if (k == 1) continue;
  console.log(k); // 0, 2
}

// Labelled break
outerloop:
for (var a = 0; a < 3; a++) {
  innerloop:
  for (var b = 0; b < 3; b++) {
    if (b == 1) break outerloop;
    console.log(a, b);
  }
}

Key Ideas

  • Use for for numeric ranges; for...of for iterating values; for...in for object keys.
  • while checks the condition first; do...while checks at the end.
  • break exits a loop; continue skips to the next iteration.
  • Labelled loops let you break out of nested loops — but use them sparingly.

Functions

Organised, reusable code — with scope, hoisting, currying, and all the rest

Functions provide organised, reusable code. Define them with a function declaration or expression. function foo() { } is a declaration — hoisted to the top of its scope. var foo = function() { }; is an expression — not hoisted. Named functions have their own name in the stack trace and can recurse using that name even if the outer variable is reassigned.

Functions create scope. Variables declared inside a function are not accessible outside. JavaScript resolves variables by looking in the current scope, then climbing up the scope chain until it finds a declaration or reaches the global scope. Inner functions can access outer variables — this is the basis of closures. A closure is a function that captures the variables of its enclosing scope, even after the outer function returns.

Currying transforms a function of n arguments into a sequence of n functions, each taking one argument. var prism = l => w => h => l * w * h; — call as prism(2)(3)(5). Immediately Invoked Function Expressions (IIFEs) are self-executing anonymous functions: (function() { alert("Hello"); })();. They were the pre-ES6 way to create private scopes.

Functions can be passed as arguments, returned as values, and assigned to variables. They are first-class citizens. bind, call, and apply control the this value. bind returns a new function with the context permanently set; call and apply invoke immediately with a given context. Default parameters (ES6) provide fallback values: function printMsg(msg = 'Default') { }. Rest parameters (...args) collect arbitrary numbers of arguments into an array.

Recursion is a function calling itself. It is powerful for tree traversal and mathematical functions, but beware of stack overflow for deep recursion. Tail Call Optimization (TCO) in strict mode can eliminate the overhead of recursive calls, but browser support is inconsistent.

// Function declaration — hoisted
foo();
function foo() { console.log('bar'); }

// Function expression — not hoisted
// bar(); // TypeError
var bar = function() { console.log('bar'); };

// IIFE
(function() {
  alert("I've run - but can't be run again");
})();

// Default parameters
function printMsg(msg = 'Default value for msg.') {
  console.log(msg);
}
printMsg(); // "Default value for msg."

// Rest parameters
function personLogsSomeThings(person, ...msg) {
  msg.forEach(arg => console.log(person, 'says', arg));
}
personLogsSomeThings('John', 'hello', 'world');

// Currying
var prism = l => w => h => l * w * h;
prism(2)(3)(5); // 30

// Recursion
function factorial(n) {
  if (n <= 1) return 1;
  return n * factorial(n - 1);
}
factorial(5); // 120

// bind
function showName(label) {
  console.log(label + ":" + this.name);
}
var student = { name: "Ravi" };
var bound = showName.bind(student);
bound("student"); // "student:Ravi"

// call and apply
function speak() {
  console.log(this.name + ": " + Array.prototype.slice.call(arguments));
}
speak.apply({name: "Sunny"}, ["I", "Code"]); // "Sunny: I,Code"
speak.call({name: "Sunny"}, "I", "<3"); // "Sunny: I,<3"

Key Ideas

  • Function declarations are hoisted; function expressions are not.
  • Functions create scope; closures capture the variables of their enclosing scope.
  • IIFEs create private scopes; default and rest parameters handle optional arguments.
  • bind, call, and apply control the this value of a function.

Functional JavaScript

Higher-order functions, pure functions, and the functional style

Functions that operate on other functions — by taking them as arguments, returning them, or both — are called higher-order functions. Passing callbacks to Array.prototype.map, filter, and reduce is using higher-order functions. So is returning a function from a function. Higher-order functions enable composition, currying, and the functional style.

A pure function is a function that, given the same input, always returns the same output — and does not modify any state outside its own scope. Pure functions are predictable, testable, and composable. They have no side effects: they don't mutate their arguments, don't read global variables, and don't write to I/O. Functional programming favors pure functions and immutability.

Function composition is the act of combining two or more functions to produce a new function. const compose = (...fns) => x => fns.reduceRight((acc, fn) => fn(acc), x); — or with reduce for left-to-right composition. Composition lets you build complex transformations from simple ones. The identity monad is a starting point for understanding monads: it wraps a value and provides bind, apply, call, and value methods that let you chain operations on the wrapped value.

Functional JavaScript encourages map/filter/reduce over explicit loops, pure functions over stateful ones, and composition over inheritance. It is not an all-or-nothing choice — you can adopt functional techniques selectively.

// Higher-order function
function iAmJustFunction(callbackFn) {
  // do some stuff ...
  callbackFn();
}
iAmJustFunction(() => console.log("callback invoked"));

// Returning a function
function iAmJustFunction2() {
  return function iAmReturnedFunction() {
    console.log("returned function invoked");
  };
}
iAmJustFunction2()();

// Pure function
const pure = (input) => {
  let output = input.a + 1;
  return output;
};

// Impure function (modifies argument)
const impure = (input) => {
  input.a = input.a + 1;
  return input.a;
};

// Composition
const compose = (...fns) => x => fns.reduceRight((acc, fn) => fn(acc), x);
const capitalize = s => s[0].toUpperCase() + s.slice(1);
const sign = s => s + ", made with love";
const formatText = compose(capitalize, sign);
formatText('this is an example'); // "This is an example, made with love"

// Accepting functions as arguments
function transform(fn, arr) {
  let result = [];
  for (let el of arr) {
    result.push(fn(el));
  }
  return result;
}
transform(x => x * 2, [1, 2, 3, 4]); // [2, 4, 6, 8]

Key Ideas

  • Higher-order functions take or return other functions — the basis of map, filter, reduce, and composition.
  • Pure functions return the same output for the same input and have no side effects.
  • Function composition builds complex transformations from simple ones.
  • Functional JavaScript favors immutability and declarative transformations over explicit loops and mutation.

Prototypes, Objects

The prototype chain — JavaScript's inheritance mechanism

In JavaScript, there are no classes in the conventional sense — there are prototypes. Every object has an internal link to another object called its prototype. When you access a property that doesn't exist on the object itself, JavaScript looks up the prototype chain. This is how inheritance works.

You can create a prototype and use Object.create(prototype) to create an object that inherits from it. var prototype = { foo: 'foo', bar: function() { return this.foo; } }; — var obj = Object.create(prototype);. Now obj.foo is 'foo' and obj.bar() returns 'foo'. Changes to the prototype are immediately visible on all objects that inherit from it.

Prototypal inheritance is made through object references and objects are completely mutable. This is powerful but dangerous: changing Object.prototype affects every object in the system, including third-party libraries. Avoid it.

Pseudo-classical inheritance emulates classical inheritance using prototypes. A constructor function sets up instance properties; its prototype provides shared methods. Foo.prototype.bar = 'bar'; — new Foo() objects have bar. The constructor property points back to the constructor. instanceof checks the prototype chain. Since ES6, the class syntax is preferred for new code, but the underlying mechanism is still prototypes.

// Plain prototype
var prototype = {
  foo: 'foo',
  bar: function() { return this.foo; }
};
var obj = Object.create(prototype);
console.log(obj.foo); // "foo"
console.log(obj.bar()); // "foo"

prototype.foo = "bar";
console.log(obj.foo); // "bar"

// Pseudo-classical inheritance
function Foo(id, name) {
  this.id = id;
  this.name = name;
}
Foo.prototype.bar = 'bar';

var foo = new Foo(1, 'foo');
console.log(foo.id);    // 1
console.log(foo.bar);   // "bar"
console.log(foo instanceof Foo);    // true
console.log(foo instanceof Object); // true

// Object.create with null prototype
let objInheritingNull = Object.create(null);
'toString' in objInheritingNull; // false

// ES6 Object.setPrototypeOf
let obj2 = Object.create({foo: 'foo'});
obj2 = Object.setPrototypeOf(obj2, {bar: 'bar'});
obj2.foo; // undefined
obj2.bar; // "bar"

Key Ideas

  • Every object has a prototype; property access climbs the prototype chain.
  • Object.create(prototype) creates a new object that inherits from the given prototype.
  • Prototypal inheritance is powerful but dangerous — avoid modifying built-in prototypes.
  • Pseudo-classical inheritance uses constructor functions and prototypes; ES6 classes are syntactic sugar over this model.

Classes

Syntactic sugar over prototypes — but much nicer to read

The class syntax (ES6) provides a cleaner way to define constructor functions and prototypes. A class is defined with the class keyword; the constructor method sets up instance state. class MyClass { constructor(option) { this.option = option; } } — instantiate with new MyClass('speedy').

Inheritance works with the extends keyword. A subclass can call the superclass constructor with super() and access superclass methods with super.method(). class SubClass extends SuperClass { constructor() { super(); this.name = 'subclass'; } }.

Static methods and properties are defined with the static keyword. They belong to the class itself, not to instances. class MyClass { static myStaticMethod() { return 'Hello'; } } — call as MyClass.myStaticMethod(). Static methods are inherited by subclasses.

Getters and setters provide custom behaviour for property access. Define them with the get and set keywords. A getter is called when the property is read; a setter when it is assigned. Private members are emulated with closures or WeakMaps — JavaScript does not have true private fields (though a proposal is in progress). Dynamic method names let you compute method names at runtime: ["add"](a, b) { return a + b; }.

// Basic class
class MyClass {
  constructor(option) {
    console.log(`Creating instance using ${option} option.`);
    this.option = option;
  }
}
const foo = new MyClass('speedy');

// Inheritance
class SuperClass {
  constructor() {
    this.logger = console.log;
  }
  log() {
    this.logger(`Hello ${this.name}`);
  }
}
class SubClass extends SuperClass {
  constructor() {
    super();
    this.name = 'subclass';
  }
}
const subClass = new SubClass();
subClass.log(); // "Hello subclass"

// Static methods
class MathHelper {
  static add(a, b) { return a + b; }
  static get PI() { return 3.14159; }
}
MathHelper.add(2, 3); // 5
MathHelper.PI;        // 3.14159

// Getters and setters
class Person {
  constructor(first, last) {
    this._first = first;
    this._last = last;
  }
  get fullName() {
    return this._first + ' ' + this._last;
  }
  set fullName(value) {
    [this._first, this._last] = value.split(' ');
  }
}
const p = new Person('John', 'Doe');
p.fullName;            // "John Doe"
p.fullName = 'Mary Jones';
p.fullName;            // "Mary Jones"

// Dynamic method names
class Car {
  ["add"](a, b) { return a + b; }
  [1 + 2]() { return "three"; }
}
const car = new Car();
car.add(4, 5); // 9
car[3]();      // "three"

Key Ideas

  • class provides cleaner syntax for constructor functions and prototypes.
  • extends and super support inheritance; static methods belong to the class, not instances.
  • Getters and setters provide custom behaviour for property access.
  • Private members are emulated with closures or WeakMaps.

Namespacing

Keep the global namespace clean

In JavaScript, everything lives in the global namespace unless you explicitly scope it. This can lead to naming collisions, especially when you use multiple libraries. Namespacing is the practice of grouping related variables and functions under a single global name.

The simplest namespacing technique is direct assignment: create a single global object and attach related functions to it. var NavigationNs = NavigationNs || {}; — then NavigationNs.active = function() {}, NavigationNs.pagination = function() {}, NavigationNs.redirection = function() {}. This replaces three global functions with one global object.

For larger systems, use nested namespaces: NavigationNs.pagination.jquery = function() {}, NavigationNs.pagination.angular = function() {}. But avoid excessive nesting — it slows down property lookup and adds unnecessary complexity.

Modern JavaScript has better tools for this: ES6 modules, IIFEs, and the export/import syntax. The namespacing pattern is still useful in older codebases, but new code should prefer modules.

// Before: three global variables
var setActivePage = function () {};
var getPage = function () {};
var redirectPage = function () {};

// After: one global namespace
var NavigationNs = NavigationNs || {};
NavigationNs.active = function() {};
NavigationNs.pagination = function() {};
NavigationNs.redirection = function() {};

// Nested namespace
var NavigationNs = NavigationNs || {};
NavigationNs.active = {};
NavigationNs.pagination = {};
NavigationNs.redirection = {};

NavigationNs.pagination.jquery = function() {};
NavigationNs.pagination.angular = function() {};
NavigationNs.pagination.ember = function() {};

Key Ideas

  • Namespacing groups related functions under a single global name to avoid collisions.
  • Direct assignment is the simplest form: var Ns = Ns || {};.
  • Nested namespaces work but should be used sparingly — too much nesting hurts performance.
  • Modern code should prefer ES6 modules over namespacing patterns.

Context (this)

The value of this depends on how a function is called

The value of this in JavaScript depends on how a function is invoked. When called as a method of an object, this refers to that object. person.bio() — this is person. When called as a standalone function, this refers to the global object (in non-strict mode) or is undefined (in strict mode). Assigning a method to a variable and calling it loses the context.

In a constructor function (called with new), this refers to the newly created object. In an arrow function, this is lexically bound — it takes the this value from the enclosing scope, regardless of how the function is called. This is why arrow functions are useful for callbacks inside methods.

bind creates a new function with this permanently set. call and apply invoke the function immediately with a given context; call takes arguments individually, apply takes them as an array. These methods are useful for borrowing methods from other objects.

The classic pitfall: using this inside a nested function loses the context. The fix is to save var self = this; or use an arrow function. Both patterns preserve the outer this.

var person = {
  name: 'John Doe',
  age: 42,
  bio: function() {
    console.log('My name is ' + this.name);
  }
};
person.bio(); // "My name is John Doe"

var bio = person.bio;
bio(); // "My name is undefined" — context lost

// Saving this
document.getElementById('myAJAXButton').onclick = function() {
  var self = this;
  makeAJAXRequest(function(result) {
    if (result) {
      self.className = 'success';
    }
  });
};

// Arrow function
document.getElementById('myAJAXButton').onclick = function() {
  makeAJAXRequest(result => {
    if (result) {
      this.className = 'success';
    }
  });
};

// bind
var monitor = {
  threshold: 5,
  check: function(value) {
    if (value > this.threshold) {
      this.display("Value is too high!");
    }
  },
  display(message) {
    alert(message);
  }
};
var check = monitor.check.bind(monitor);
check(15); // works

// call and apply
function print() {
  console.log(this.toPrint);
}
print.apply({ toPrint: "Foo" }); // "Foo"
print.call({ toPrint: "Foo" });  // "Foo"

// Constructor this
function Cat(name) {
  this.name = name;
  this.sound = "Meow";
}
var cat = new Cat("Tom");
cat.sound; // "Meow"

Key Ideas

  • The value of this depends on how a function is called: method, standalone, constructor, or bound.
  • Arrow functions lexically bind this — they inherit it from the enclosing scope.
  • Use var self = this or arrow functions to preserve context in callbacks.
  • bind, call, and apply let you control the this value explicitly.

Setters and Getters

Custom behaviour for property access

Setters and getters are object properties that call a function when they are set or gotten. Define them with Object.defineProperty or with the get and set keywords in an object literal. Object.defineProperty(obj, "objProperty", { get: function() { return "a value"; }, set: function(value) { setValue = value; } });.

In an object literal, getters and setters can be defined inline. var date = { year: '2017', month: '02', day: '27', get date() { return `${this.year}-${this.month}-${this.day}`; }, set date(dateString) { /* parse and set */ } };. Reading date.date calls the getter; assigning date.date = '2018-01-02' calls the setter.

In ES6 classes, getters and setters are defined with the get and set keywords. get firstname() { return this._firstname; }. Note the underscore prefix — a convention indicating that the underlying property is intended to be private, though JavaScript doesn't enforce it.

Getters and setters are a form of metaprogramming: they let you intercept property access and run arbitrary code. They are useful for validation, computed properties, and lazy initialization. But they can also hide complexity and make debugging harder — use them thoughtfully.

// Object.defineProperty
var setValue;
var obj = {};
Object.defineProperty(obj, "objProperty", {
  get: function() {
    return "a value";
  },
  set: function(value) {
    setValue = value;
  }
});

// Object literal
var date = {
  year: '2017',
  month: '02',
  day: '27',
  get date() {
    return `${this.year}-${this.month}-${this.day}`;
  },
  set date(dateString) {
    var dateRegExp = /(\d{4})-(\d{2})-(\d{2})/;
    if (dateRegExp.test(dateString)) {
      var parsedDate = dateRegExp.exec(dateString);
      this.year = parsedDate[1];
      this.month = parsedDate[2];
      this.day = parsedDate[3];
    } else {
      throw new Error('Date string must be in YYYY-MM-DD format');
    }
  }
};
date.date;            // "2017-02-27"
date.date = '2018-01-02';
date.year;            // "2018"

// ES6 class
class Person {
  constructor(firstname, lastname) {
    this._firstname = firstname;
    this._lastname = lastname;
  }
  get firstname() {
    return this._firstname;
  }
  set firstname(name) {
    this._firstname = name;
  }
  get lastname() {
    return this._lastname;
  }
  set lastname(name) {
    this._lastname = name;
  }
}
let person = new Person('John', 'Doe');
person.firstname; // "John"
person.firstname = 'Foo';
person.firstname; // "Foo"

Key Ideas

  • Getters and setters intercept property access and run arbitrary code.
  • Define them with Object.defineProperty or the get/set keywords in object literals and classes.
  • Use them for validation, computed properties, and lazy initialization.
  • Be careful — they can hide complexity and make debugging harder.

Events

Reacting to the browser's lifecycle

The browser fires many events during a page's lifecycle. The three most important load-related events are onload, DOMContentLoaded, and the self-invoking anonymous function. They fire at different times, and understanding the difference is crucial for scripts that manipulate the DOM.

window.onload (or <body onload="...">) fires after all the contents of the page — images, stylesheets, scripts — are completely loaded. This is the latest of the load events, and the safest for scripts that need everything available.

DOMContentLoaded fires after the DOM has been constructed, but before external resources like images and stylesheets are loaded. It is often faster than onload and is suitable for most DOM manipulation scripts. Attach it with document.addEventListener("DOMContentLoaded", function() { ... });.

A self-invoking anonymous function (IIFE) executes as soon as the browser encounters it — potentially before the DOM is even loaded. This is the earliest possible execution, and should be used only for code that doesn't touch the DOM.

// onload — fires after everything is loaded
<body onload="someFunction()">
  <img src="image1" />
  <img src="image2" />
</body>
<script>
function someFunction() {
  console.log("Hi! I am loaded");
}
</script>

// DOMContentLoaded — fires after DOM is built
document.addEventListener("DOMContentLoaded", function(event) {
  console.log("Hello! I am loaded");
});

// IIFE — fires immediately
(function() {
  console.log("Hi I am an anonymous function! I am loaded");
})();

Key Ideas

  • onload fires after all resources load; DOMContentLoaded fires after the DOM is built; IIFEs run immediately.
  • Use DOMContentLoaded for most DOM manipulation — it's faster than onload.
  • Use onload when you need images and stylesheets available.
  • Use IIFEs only for code that doesn't touch the DOM.

Inheritance

Prototypal, pseudo-classical, and ES6 class inheritance

Inheritance in JavaScript is built on prototypes. A standard function prototype lets you define properties and methods on Foo.prototype that are shared by all instances created with new Foo(). Foo.prototype.bar = function() { return 'I am bar'; };. Instances inherit these methods through the prototype chain.

Prototypal inheritance creates a new object from a prototype with Object.create(prototype). Changes to the prototype are immediately visible on all inheriting objects. Object references are mutable, so modifications propagate. This is powerful but requires care — especially with Object.prototype, which every object inherits from.

Pseudo-classical inheritance emulates classical inheritance using prototypes. A constructor function defines instance properties; its prototype defines shared methods. Foo.prototype.bar = 'bar'; — instances of Foo get bar. The constructor property points back to the constructor function. instanceof checks the prototype chain. This was the standard pattern in ES5 and earlier.

Since ES6, the class syntax is preferred. Classes support extends and super, and are conceptually cleaner. But underneath, they are still prototypes. Object.setPrototypeOf() lets you change an object's prototype, but it is very slow — prefer creating objects with the desired prototype from the start.

// Standard function prototype
function Foo() {}
Foo.prototype.bar = function() {
  return 'I am bar';
};
var foo = new Foo();
console.log(foo.bar()); // "I am bar"

// Prototypal inheritance
var prototype = { foo: 'foo', bar: function() { return this.foo; } };
var obj = Object.create(prototype);
console.log(obj.foo); // "foo"

// Pseudo-classical inheritance
function Person(name) {
  this.name = name;
}
Person.prototype.sayHello = function() {
  return 'Hello, ' + this.name;
};
var alice = new Person('Alice');
alice.sayHello(); // "Hello, Alice"

// ES6 class inheritance
class Animal {
  constructor(name) {
    this.name = name;
  }
  speak() {
    return this.name + ' makes a sound';
  }
}
class Dog extends Animal {
  speak() {
    return this.name + ' barks';
  }
}
const dog = new Dog('Rex');
dog.speak(); // "Rex barks"

// setPrototypeOf (slow, use sparingly)
let obj2 = Object.create({foo: 'foo'});
obj2 = Object.setPrototypeOf(obj2, {bar: 'bar'});
obj2.foo; // undefined
obj2.bar; // "bar"

Key Ideas

  • JavaScript inheritance is based on prototypes, not classes.
  • Object.create(prototype) creates an object that inherits from the given prototype.
  • Pseudo-classical inheritance uses constructor functions and prototypes; ES6 classes are syntactic sugar over this model.
  • Avoid changing Object.prototype — it affects every object in the system.

Method Chaining

Design objects whose methods return themselves

Method chaining is a design methodology where each method returns a reference to the object itself, allowing multiple method calls to be chained together. vec.add({x:10,y:10}).add({x:10,y:10}).log(). This makes the code more readable and expressive.

To make an object chainable, each method must return this. The constructor sets up the state; the methods modify it and return the instance. Chainable objects should be all-or-nothing: if only some methods return this, callers can't predict the behaviour.

Not all methods should be chainable. A .toString() method returns a string; .clone() returns a new instance; .get() returns a value. Naming should make the return type unambiguous. Use .log() for a chainable debug output, .toString() for a string return.

The convention for chaining is to put each call on its own line, indented, with the dot at the beginning of the line. This makes long chains readable and makes it easy to comment out individual steps. Semicolons at the end of the chain make the end explicit.

// Chainable vector class
function Vec(x = 0, y = 0) {
  this.x = x;
  this.y = y;
}
Vec.prototype = {
  add: function(vec) {
    this.x += vec.x;
    this.y += vec.y;
    return this;
  },
  scale: function(val) {
    this.x *= val;
    this.y *= val;
    return this;
  },
  log: function() {
    console.log(this.x + ' : ' + this.y);
    return this;
  },
  clone: function() {
    return new Vec(this.x, this.y);
  }
};

var vec = new Vec();
vec.add({x: 10, y: 10})
   .add({x: 10, y: 10})
   .log() // "20 : 20"
   .add({x: 10, y: 10})
   .scale(1 / 30)
   .log() // "1 : 1"
   .clone()
   .scale(2)
   .log(); // "2 : 2"

Key Ideas

  • Method chaining returns this from each method, allowing multiple calls in sequence.
  • Not all methods should be chainable — naming should make the return type clear.
  • Format chains with one call per line, dot at the beginning, for readability.

Callbacks

Functions passed to other functions — the original async pattern

A callback is a function passed to another function as an argument, to be invoked when some operation completes. Callbacks are the original way to handle asynchronous behaviour in JavaScript. They are also used for event handling, iteration, and dependency injection.

The classic example is setTimeout(callback, delay). The callback runs after the delay. Another is array.forEach(callback). The callback runs for each element. jQuery.getJSON(url, callback) fetches data and passes it to the callback when ready.

Callbacks have a famous pitfall: "callback hell." When callbacks are nested inside callbacks, code becomes deeply indented and hard to read. Promises and async/await were invented to solve this problem. But callbacks are still useful, and understanding them is essential to understanding Promises.

Inside a callback, the value of this is lost unless you bind it or use an arrow function. The classic fix is var self = this; or function() {}.bind(this). Arrow functions bind this automatically.

// Simple callback
function foo(array, callback) {
  var sum = 0;
  for (var i = 0; i < array.length; i++) {
    callback(array[i]);
    sum += array[i];
  }
  return sum;
}

var array = [];
foo(array, alert);
foo(array, function (x) {
  console.log(x);
});

// Asynchronous callback
$.getJSON("foo.json", {}, function(data) {
  // data handling code
});

// Callbacks and this
function SomeClass(msg, elem) {
  this.msg = msg;
  elem.addEventListener('click', function() {
    console.log(this.msg); // undefined — this is lost
  });
}

// Fix with bind
elem.addEventListener('click', function() {
  console.log(this.msg);
}.bind(this));

// Fix with arrow function
elem.addEventListener('click', () => {
  console.log(this.msg);
});

// Error handling with callbacks
function compare(actual, success, failure) {
  if (actual === expected) {
    success();
  } else {
    failure();
  }
}
compare(true, onSuccess, onFailure);
compare(false, onSuccess, onFailure);

Key Ideas

  • Callbacks are functions passed to other functions, invoked when some operation completes.
  • Asynchronous callbacks let you handle results that arrive later.
  • Inside a callback, this is lost unless bound or replaced with an arrow function.
  • Callbacks can be used for success/failure branching, but Promises are often cleaner.

Intervals and Timeouts

Scheduling code to run later — or repeatedly

setTimeout(callback, milliseconds) executes a function after a specified delay. setInterval(callback, milliseconds) executes a function repeatedly at a specified interval. Both return an ID that can be passed to clearTimeout or clearInterval to cancel the scheduled execution.

setTimeout is not a sleep function. The callback is queued to run after the delay, but if the main thread is busy, it runs later. JavaScript is single-threaded; timers are managed by the event loop. A setTimeout(fn, 0) does not run immediately — it pushes the callback to the end of the execution queue.

For recursive execution with a delay between runs, use recursive setTimeout rather than setInterval. This ensures the delay starts after the function completes, not at the moment the function starts. It also prevents overlapping executions.

A common pitfall: using setTimeout inside a loop with a var index variable. All callbacks see the final value of the variable. Fix it with an IIFE or let (which creates a new binding per iteration).

// setTimeout
setTimeout(function() {
  console.log('hello');
}, 1000);

// setInterval
var interval = setInterval(function() {
  console.log("This will be logged every 5 seconds");
}, 5000);

// clearInterval
setTimeout(function() {
  clearInterval(interval);
}, 32000);

// clearTimeout
var timeout = setTimeout(function() {
  console.log('hello');
}, 1000);
clearTimeout(timeout);

// Recursive setTimeout
function repeatingFunc() {
  console.log("It's been 5 seconds.");
  setTimeout(repeatingFunc, 5000);
}
setTimeout(repeatingFunc, 5000);

// The classic loop bug
for (var i = 0; i < 3; ++i) {
  setTimeout(function() {
    console.log(i); // 3, 3, 3
  }, 500);
}

// Fixed with let
for (let i = 0; i < 3; ++i) {
  setTimeout(function() {
    console.log(i); // 0, 1, 2
  }, 500);
}

Key Ideas

  • setTimeout runs a function once after a delay; setInterval runs it repeatedly.
  • Both return IDs that can be passed to clearTimeout or clearInterval.
  • Use recursive setTimeout instead of setInterval to avoid overlapping executions.
  • When looping with timers, use let or an IIFE to capture the current index.

Regular Expressions

Patterns for matching, extracting, and replacing text

Regular expressions are patterns for matching text. Create them with the RegExp constructor — new RegExp(".*") — or as a literal — /.*/. The literal form is preferred when the pattern is static; the constructor is useful when the pattern is built from variables. Flags can be appended: g (global), m (multiline), i (case-insensitive), u (unicode), y (sticky).

The .test() method returns true if the pattern matches the string. .exec() returns an array of matches, or null. String methods .match(), .replace(), .split(), and .search() accept regular expressions as arguments. .replace() can take a replacement string or a callback function that receives the match and returns the replacement.

Groups are created with parentheses. They capture parts of the match. /([a-z])\+/g captures the letter before a +. Use $1, $2, etc. in the replacement string, or the second argument of the replacement callback, to access captured groups.

Look-aheads let you test for a pattern without including it in the match. (?=pattern) is a positive look-ahead; (?!pattern) is a negative look-ahead. Non-capturing groups (?:pattern) group without capturing.

// Literal and constructor forms
var re1 = /.*/;
var re2 = new RegExp(".*");
var re3 = /.*/gmi;
var re4 = new RegExp("\\w*");

// test
var re = /[a-z]+/;
if (re.test("foo")) {
  console.log("Match exists.");
}

// exec
var re2 = /([0-9]+)[a-z]+/;
var match = re2.exec("foo123bar");
// match[0] === "123bar", match[1] === "123"

// match, replace, split, search
"string".match(/[i-n]+/);      // ["in"]
"string".replace(/[i-n]+/, "foo"); // "strfoog"
"stringstring".split(/[i-n]+/); // ["str", "gstr", "g"]
"string".search(/[i-n]+/);     // 3

// Replacing with a callback
"Some string Some".replace(/Some/g, (match, startIndex, wholeString) => {
  if (startIndex == 0) {
    return 'Start';
  } else {
    return 'End';
  }
});
// "Start string End"

// Groups
let str = "aa+b+cc+1+2";
str.replace(/([a-z])\+/g, '$1 '); // "aa b cc 1+2"

// Look-ahead
str.replace(/\+(?=[a-z])/g, ' '); // "aa b cc+1+2"

Key Ideas

  • Create regular expressions with literals (/pattern/) or the RegExp constructor.
  • Flags g, m, i, u, y modify matching behaviour.
  • Use .test() for a boolean check; .exec() for detailed matches; .replace() for substitution.
  • Groups (parentheses) capture parts of the match; look-aheads test without capturing.

Cookies

Small pieces of data stored in the browser

Cookies are small pieces of data stored by the browser and sent back to the server with every request to the same domain. They are useful for session management, personalization, and tracking. The document.cookie property lets you read and write cookies from JavaScript.

To check if cookies are enabled, use navigator.cookieEnabled. To add a cookie, assign to document.cookie: document.cookie = "name=value; expires=date; path=/";. The expires attribute sets the expiration date; without it, the cookie is a session cookie and is deleted when the browser closes. The path attribute restricts the cookie to a specific path.

Reading cookies is awkward: document.cookie returns a semicolon-separated string of all cookies. You have to split and parse it yourself. Removing cookies is done by setting the expiration date to a past date. document.cookie = name + "=; expires=" + expiry.toGMTString() + "; path=/";.

Cookies have limitations: they are small (about 4KB), they are sent with every request (wasting bandwidth), and they have security issues (CSRF). For larger data, use Web Storage. For security-sensitive data, use server-side sessions.

// Check if cookies are enabled
if (navigator.cookieEnabled === false) {
  alert("Error: cookies not enabled!");
}

// Set a cookie
var COOKIE_NAME = "Example Cookie";
var COOKIE_VALUE = "Hello, world!";
var COOKIE_PATH = "/foo/bar";
var COOKIE_EXPIRES = (new Date(Date.now() + 60000)).toUTCString();
document.cookie +=
  COOKIE_NAME + "=" + COOKIE_VALUE
  + "; expires=" + COOKIE_EXPIRES
  + "; path=" + COOKIE_PATH;

// Read cookies
var name = "Example Cookie=";
var cookie_array = document.cookie.split(';');
var cookie_value;
for (var i = 0; i < cookie_array.length; i++) {
  var cookie = cookie_array[i];
  while (cookie.charAt(0) == ' ') {
    cookie = cookie.substring(1, cookie.length);
  }
  if (cookie.indexOf(name) == 0) {
    cookie_value = cookie.substring(name.length, cookie.length);
  }
}

// Remove a cookie
var expiry = new Date();
expiry.setTime(expiry.getTime() - 3600);
document.cookie = "Example Cookie=; expires=" + expiry.toGMTString() + "; path=/";

Key Ideas

  • Cookies are small data stores sent with every same-origin request.
  • document.cookie reads and writes cookies — but reading requires string parsing.
  • Set expires to make a persistent cookie; omit it for a session cookie.
  • Remove a cookie by setting an expiration date in the past.

Web Storage

localStorage and sessionStorage — bigger, simpler, faster than cookies

localStorage and sessionStorage provide key-value storage of strings in the browser. localStorage persists indefinitely (unless the user clears it); sessionStorage persists only for the lifetime of the tab or window. Both are limited to about 5–10 MB, depending on the browser.

Use localStorage.setItem(key, value) to store a value, localStorage.getItem(key) to retrieve it, and localStorage.removeItem(key) to delete it. To clear all data, use localStorage.clear(). Values must be strings; for objects, use JSON.stringify() to store and JSON.parse() to retrieve.

You can also treat localStorage as a JavaScript object: localStorage.greet = "Hi!"; is equivalent to localStorage.setItem("greet", "Hi!"). This is convenient but less explicit.

Storage events fire when localStorage changes in another tab or window. This lets you synchronize state between pages without reloading. window.addEventListener('storage', function(event) { ... });. Session storage does not fire cross-window events.

// localStorage basics
localStorage.setItem('name', "John Smith");
console.log(localStorage.getItem('name')); // "John Smith"
localStorage.removeItem('name');
console.log(localStorage.getItem('name')); // null

// Storing objects
var players = [{name: "Tyler", score: 22}, {name: "Ryan", score: 41}];
localStorage.setItem('players', JSON.stringify(players));
console.log(JSON.parse(localStorage.getItem('players')));

// Simpler object-like syntax
localStorage.greet = "Hi!";
localStorage.greet; // "Hi!"
delete localStorage.greet;
localStorage.clear();

// sessionStorage
sessionStorage.setItem('volume', '0.5');
var volume = Number(sessionStorage.getItem('volume') || 1.0);

// Storage events
window.addEventListener('storage', function(event) {
  if (event.key === 'user-value') {
    document.getElementById('output').textContent = event.newValue;
  }
});

// localStorage length
localStorage.setItem('StackOverflow', 'Documentation');
localStorage.setItem('font', 'Helvetica');
localStorage.setItem('image', 'sprite.svg');
localStorage.length; // 3

Key Ideas

  • localStorage persists across sessions; sessionStorage lasts only for the tab.
  • Both store only strings; use JSON.stringify and JSON.parse for objects.
  • Both have a .length property, a .clear() method, and .removeItem().
  • Storage events fire across tabs, enabling cross-window synchronization.

Data Attributes

Custom data stored in HTML elements

Data attributes are custom attributes on HTML elements, prefixed with data-. They are used to store extra information about an element without using non-standard attributes or hacks. <li data-id="US" data-dial-code="1">USA</li>.

The dataset property provides read and write access to all data-* attributes on an element. element.dataset.id reads the data-id attribute; element.dataset.dialCode reads data-dial-code (camelCase conversion). Assigning to dataset sets the attribute.

Data attributes are a great way to associate metadata with DOM elements without polluting the global namespace or creating custom attributes. Use them for IDs, configuration, or any extra data that doesn't belong in standard HTML attributes.

JSON

A lightweight data-interchange format — not JavaScript, but close

JSON (JavaScript Object Notation) is a lightweight data-interchange format. It is easy for humans to read and write, and easy for machines to parse and generate. But note: in JavaScript, JSON is a string, not an object. A "JSON string" is a string containing JSON text; when you parse it, you get a JavaScript value.

JSON.stringify(value, replacer, space) serializes a JavaScript value to a JSON string. JSON.parse(text, reviver) parses a JSON string into a JavaScript value. replacer can filter or transform values during serialization; reviver can do the same during parsing. space adds indentation for readability.

JSON supports strings, numbers, booleans, null, arrays, and objects. It does not support undefined, functions, symbols, or circular references. undefined properties are omitted from serialization. NaN and Infinity become null. Dates are serialized as ISO strings.

A common mistake is to treat a JavaScript literal as JSON. JSON requires double quotes around property names and string values. Single quotes, trailing commas, and unquoted keys are all syntax errors in JSON. Use JSON.parse to parse JSON strings, and JSON.stringify to serialize. Never use eval — it's a security risk and slower.

// Parsing
var jsonString = '[{"name":"John","score":51},{"name":"Jack","score":17}]';
var data = JSON.parse(jsonString);

// Parsing with reviver
var data2 = JSON.parse(jsonString, function reviver(key, value) {
  return key === 'name' ? value.toUpperCase() : value;
});

// Serializing
JSON.stringify(true);          // 'true'
JSON.stringify(12);            // '12'
JSON.stringify('foo');         // '"foo"'
JSON.stringify({foo: 'baz'});  // '{"foo": "baz"}'
JSON.stringify([1, true, 'foo']); // '[1, true, "foo"]'

// Replacer function
function replacer(key, value) {
  if (typeof value === "string") {
    return undefined; // filter out strings
  }
  return value;
}
JSON.stringify({ foundation: "Mozilla", model: "box", week: 45 }, replacer);
// '{"week": 45}'

// Replacer array
JSON.stringify({foo: 1, bar: 2, baz: 3}, ['foo', 'bar']); // '{"foo": 1, "bar": 2}'

// Space for indentation
JSON.stringify({x: 1, y: 1}, null, 2);
/*
{
  "x": 1,
  "y": 1
}
*/

// Cyclic structures throw
const world = { name: 'World', regions: [] };
world.regions.push({ name: 'Asia', parent: world });
// JSON.stringify(world); // TypeError: Converting circular structure to JSON

Key Ideas

  • JSON is a string format; it is not JavaScript.
  • Use JSON.parse to parse and JSON.stringify to serialize.
  • JSON supports only strings, numbers, booleans, null, arrays, and objects.
  • Use a reviver or replacer function to filter or transform values.

AJAX

Asynchronous JavaScript and XML — fetching data without reloading the page

AJAX stands for "Asynchronous JavaScript and XML." It allows the browser to communicate with a server without reloading the page. Despite the name, JSON is more commonly used than XML because of its simpler formatting and lower redundancy.

The classic way to make an AJAX request is with XMLHttpRequest. Create an instance, open a connection with xhr.open(method, url, async), set an onreadystatechange handler, and send the request with xhr.send(). When readyState === 4 and status === 200, the response is ready.

Modern code uses fetch(), which returns a Promise. fetch(url).then(response => response.json()).then(data => { ... }). Fetch is cleaner and more powerful, but requires Promise support. For older browsers, use XMLHttpRequest or a library like Axios.

AJAX requests are asynchronous by default. The fetch promise resolves when the response headers are received; the body may still be loading. Use response.json(), response.text(), or response.blob() to read the body. Handle errors with .catch(). Check response.ok to detect HTTP errors (4xx, 5xx).

// XMLHttpRequest
var xhttp = new XMLHttpRequest();
xhttp.onreadystatechange = function() {
  if (xhttp.readyState === XMLHttpRequest.DONE && xhttp.status === 200) {
    console.log(xhttp.responseText);
  }
};
xhttp.open("GET", "ajax_info.txt", true);
xhttp.send();

// Sending JSON via POST with fetch
const requestData = { method: 'getUsers' };
const usersPromise = fetch('/api', {
  method: 'POST',
  body: JSON.stringify(requestData)
}).then(response => {
  if (!response.ok) {
    throw new Error("Got non-2XX response from API server.");
  }
  return response.json();
}).then(responseData => {
  return responseData.users;
});
usersPromise.then(users => {
  console.log("Known users: ", users);
}, error => {
  console.error("Failed to fetch users due to error: ", error);
});

// GET with parameters
function ajax(file, params, callback) {
  var url = file + '?';
  var notFirst = false;
  for (var key in params) {
    if (params.hasOwnProperty(key)) {
      url += (notFirst ? '&' : '') + key + "=" + params[key];
    }
    notFirst = true;
  }
  var xmlhttp = new XMLHttpRequest();
  xmlhttp.onreadystatechange = function() {
    if (xmlhttp.readyState == 4 && xmlhttp.status == 200) {
      callback(xmlhttp.responseText);
    }
  };
  xmlhttp.open('GET', url, true);
  xmlhttp.send();
}

  console.log(response);
});

Key Ideas

  • AJAX allows asynchronous communication with a server without reloading the page.
  • XMLHttpRequest is the classic API; fetch is the modern Promise-based API.
  • Fetch returns a Promise; use .json(), .text(), or .blob() to read the body.
  • Handle errors with .catch() and check response.ok for HTTP errors.

Enumerations

Simulating enums with objects, symbols, and automatic values

JavaScript does not have native enumerations, but you can simulate them. The simplest way is an object with named constants: const TestEnum = { One: 1, Two: 2, Three: 3 };. Add Object.freeze() to prevent modification: Object.freeze(TestEnum);.

For automatic enumeration values, you can generate them from a list of names. enumList.forEach((item, index) => enumObj[item] = index + 1); — then freeze the object. This ensures each enum has a unique value, even if you reorder the list.

ES6 symbols provide a more robust way to create unique enums. const Regnum_Animale = Symbol(); — each symbol is unique and immutable. Use symbols as values in a switch statement or as keys in an object. They cannot collide with other values.

Printing an enum variable: you can log the value or find the corresponding name. for (var name in ce) { if (ce[name] == ce.BLACK) console.log(name); } prints the name. But with symbols, you must maintain a separate map of names to symbols.

// Enum with Object.freeze
const TestEnum = Object.freeze({
  One: 1,
  Two: 2,
  Three: 3
});
var x = TestEnum.Two;
switch (x) {
  case TestEnum.One:
    console.log("111");
    break;
  case TestEnum.Two:
    console.log("222");
}

// Alternate definition

  WHITE: 0,
  GRAY: 1,
  BLACK: 2
};
Object.freeze(ColorsEnum);

// Printing an enum variable

  console.log(color); // 2
  var ce = ColorsEnum;
  for (var name in ce) {
    if (ce[name] == ce.BLACK) {
      console.log(name); // "BLACK"
    }
  }
}

      return "Vegetable kingdom";
    case Regnum_Lapideum:
      return "Mineral kingdom";
  }
}

  var enumList = ["One", "Two", "Three"];

  • Simulate enums with frozen objects of named constants.
  • Use symbols for unique, collision-free enum values.

Map

Key-value collections where keys can be anything

A Map is a key-value collection. Unlike plain objects, its keys can be any type — primitives, objects, functions. Iteration over a Map is always done in the order the items were inserted; iteration over an object's keys is not guaranteed. new Map() creates a Map; new Map([[key1, value1], [key2, value2]]) initializes it from an iterable of key-value pairs.

Use map.set(key, value) to add or update an entry; map.get(key) to retrieve; map.delete(key) to remove; map.has(key) to check for existence; map.clear() to remove all entries; map.size to get the number of entries. set returns the map, so you can chain calls: map.set(1, 2).set(3, 4).

Iterate a Map with for...of, .keys(), .values(), .entries(), or .forEach(). for (const [key, value] of map) { ... } destructures each entry. map.forEach((value, key, theMap) => { ... }) provides the value first, then the key, then the map.

Maps are useful when you need keys that aren't strings or symbols, or when you need predictable iteration order. For simple string-keyed data, plain objects are often sufficient.

// Create a Map
const map = new Map();
map.set('abc', 1).set('def', 2);

// From an iterable
const map2 = new Map([
  [new Date(), {foo: "bar"}],
  [document.body, "body"]
]);

// Get, set, delete, has
map.get('abc');  // 1
map.has('abc');  // true
map.delete('abc');
map.get('abc');  // undefined

// Size
const map3 = new Map([[1, 2], [3, 4]]);
map3.size; // 2
map3.clear();
map3.size; // 0

// Iteration
const map4 = new Map([[1, 2], [3, 4]]);
for (const [key, value] of map4) {
  console.log(`key: ${key}, value: ${value}`);
}
for (const key of map4.keys()) {
  console.log(key); // 1, then 3
}
for (const value of map4.values()) {
  console.log(value); // 2, then 4
}
map4.forEach((value, key, theMap) => {
  console.log(`key: ${key}, value: ${value}`);
});

Key Ideas

  • Map keys can be any type — primitives, objects, functions.
  • Iteration order is insertion order; objects don't guarantee order.
  • Use set, get, delete, has, clear, and size.
  • Iterate with for...of, .keys(), .values(), .entries(), or .forEach().

Timestamps

Measuring time in milliseconds — and microseconds

The standard timestamp in JavaScript is the number of milliseconds since 1 January 1970 UTC. Date.now() returns this number directly; (new Date()).getTime() returns it from a Date instance. performance.now() returns a high-resolution timestamp — the number of milliseconds since the page started loading, with microsecond precision.

To get the timestamp in seconds, divide by 1000 and floor: Math.floor(Date.now() / 1000). This is useful for Unix-style timestamps that many APIs expect.

For older browsers without Date.now(), use (new Date()).getTime(), or polyfill: if (!Date.now) { Date.now = function() { return new Date().getTime(); }; }. performance.now() is available in all modern browsers but not in older ones.

// High-resolution timestamp (microseconds)

// From a Date instance
(new Date()).getTime();

// Polyfill for old browsers

  Date.now = function now() {

  • Date.now() and getTime() return milliseconds since the epoch.
  • performance.now() returns high-resolution timestamps with microsecond precision.
  • Divide by 1000 to get Unix-style timestamps in seconds.

Unary Operators

typeof, delete, void, +, -, ~, ! — one operand at a time

Unary operators operate on a single operand. They are more efficient than standard function calls and cannot be overridden. JavaScript has seven unary operators: typeof (returns the type as a string), delete (removes a property from an object), void (discards an expression's return value), unary + (converts to Number), unary - (converts to Number then negates), ~ (bitwise NOT), and ! (logical NOT).

typeof returns one of: "undefined", "object", "boolean", "number", "string", "symbol", "function", or an implementation-defined string. Note that typeof null is "object" — a historical bug. And typeof document.all is "undefined" — a deliberate legacy exception.

The unary + operator is the fastest way to convert a value to a number. +"42" is 42; +true is 1; +null is 0; +undefined is NaN; +"foo" is NaN. The unary - does the same but negates the result. void 0 returns undefined — useful because undefined can be shadowed. !value returns false for truthy values and true for falsy values; !!value converts to boolean.

Generators

Functions that can pause and resume — coroutines in JavaScript

A generator function is declared with function*. When called, its body is not immediately executed; instead, it returns a generator object. Calling .next() on the generator steps through the function's execution. A yield expression pauses execution and returns a value; the next call to .next() resumes from that point. The return value of .next() is an object with value and done properties.

Generators are iterable: you can use them with for...of, the spread operator, and other constructs that consume iterables. They are also observers: you can send values back into the generator by passing them to .next(value). And you can delegate to another generator with yield*.

Generators are a foundation for async programming. Libraries like co and q use generators to write asynchronous code in a synchronous style: var result = yield someAsyncResult();. The generator pauses until the promise resolves, then resumes with the resolved value. This pattern is now largely superseded by async/await, but generators are still useful for lazy iteration and coroutines.

Early exit from a generator: generator.return(value) immediately terminates the generator and returns an object with done: true. Throwing an error into the generator: generator.throw(error) raises an error at the current yield expression, which can be caught by try/catch inside the generator.

  yield 1;
  console.log('yielded 1');
  yield 2;
  console.log('yielded 2');
  yield 3;
  console.log('yielded 3');
}

Promises

Representing the eventual result of an asynchronous operation

A Promise represents an operation that has produced, or will eventually produce, a value. It has three states: pending (not yet complete), fulfilled (success with a value), and rejected (failure with a reason). Once settled, a Promise is immutable. Use .then(onFulfilled, onRejected) or .then(onFulfilled).catch(onRejected) to attach callbacks.

Promises chain: .then() returns a new Promise. Returning a value from a .then() callback resolves the new Promise with that value. Returning a Promise from a .then() callback chains it. Throwing an error from a .then() callback rejects the new Promise. This lets you express complex asynchronous flows as chains of .then() calls.

Promise.all(promises) waits for all promises to resolve and returns an array of their results; it rejects if any promise rejects. Promise.race(promises) returns a promise that resolves or rejects as soon as the first promise settles. Promise.resolve(value) and Promise.reject(reason) create settled promises.

Promises are the foundation of async/await. An async function returns a Promise; await pauses until the Promise settles. Inside try/catch, await lets you handle errors synchronously. Promises can be combined with Promise.all to run operations in parallel.

// Creating a Promise
const promise = new Promise((resolve, reject) => {
  const value = doSomeWork();
  if (value) {
    resolve(value);
  } else {
    reject(new Error("Failed"));
  }
});

// Chaining
promise
  .then(value => { /* handle value */ })
  .catch(reason => { /* handle error */ });

// Promise.all
Promise.all([
  resolve(1, 5000),
  resolve(2, 6000),
  resolve(3, 7000)
]).then(values => console.log(values)); // [1, 2, 3] after 7s

// Promise.race
Promise.race([
  resolve(1, 5000),
  resolve(2, 3000),
  resolve(3, 1000)
]).then(value => console.log(value)); // 3 after 1s

// Reduce an array to chained promises
[1, 3, 5, 7, 9].reduce((seq, n) => {
  return seq.then(() => {
    console.log(n);
    return new Promise(res => setTimeout(res, 1000));
  });
}, Promise.resolve()).then(
  () => console.log('done'),
  (e) => console.log(e)
);

// Promisifying a callback function
function promiseFooFn(options) {
  return new Promise((resolve, reject) =>
    fooFn(options, (err, result) =>
      err ? reject(err) : resolve(result)
    )
  );
}

// Async/await
async function getJSON(url) {
  try {
    const response = await fetch(url);
    return await response.json();
  } catch (err) {
    console.error(err.message);
  }
}

Key Ideas

  • Promises represent future values; they can be pending, fulfilled, or rejected.
  • .then() chains operations; .catch() handles errors; returning a value resolves the next promise.
  • Promise.all waits for all; Promise.race waits for the first.
  • Async/await provides cleaner syntax for promises, with try/catch for errors.

Set

Collections of unique values, in insertion order

A Set is a collection of unique values. Unlike an array, a Set cannot contain duplicates. new Set() creates an empty Set; new Set([1, 2, 2, 3]) creates a Set containing {1, 2, 3}. Values can be primitives or object references; distinct values are determined using the SameValueZero comparison algorithm.

Use set.add(value) to add a value; set.delete(value) to remove it; set.has(value) to check for existence; set.clear() to remove all values; set.size to get the count. add returns the Set, so calls can be chained: set.add(1).add(2).add(3).

Iterate a Set with for...of or .forEach(). Insertion order is preserved. To convert a Set to an array, use Array.from(set) or [...set]. To compute intersections or differences, convert to arrays, filter, and convert back.

History

pushState, replaceState, and the browser's session history

The history object lets you manipulate the browser's session history. history.pushState(state, title, url) adds a new entry to the history stack, updates the URL, and (optionally) updates the title. The state object can be any serializable value; it's stored with the history entry and can be retrieved later with history.state.

history.replaceState(state, title, url) modifies the current history entry instead of creating a new one. This is useful for updating the URL without adding a new entry — for example, when the user filters a list.

history.go(n) loads a specific entry from the history stack. history.go(-1) goes back one page; history.go(1) goes forward. history.back() and history.forward() are shortcuts for go(-1) and go(1).

When the user navigates using the back/forward buttons, the popstate event fires. Listen for it: window.addEventListener('popstate', function(event) { ... });. The event's state property contains the state object from the history entry. This is the basis of client-side routing.

The Event Loop

How JavaScript handles asynchrony with a single thread

JavaScript runs in a single thread, but it handles asynchrony through the event loop. The event loop continuously waits for tasks to be posted, and runs each task to completion. Tasks come from the script itself, from timers, from user events, and from I/O. Each task is added to a queue; the event loop picks them up in order.

A simple example: console.log("this is a script entry point"); document.body.onclick = () => { console.log("onclick"); }; setTimeout(() => { console.log("setTimeout callback"); }, 100);. The script runs to completion first. Then the event loop waits. If the user clicks, a task is posted to run the click handler. After 100 milliseconds, the setTimeout task is posted and run.

Each event loop task "runs to completion." It is not possible to interrupt a block of code that is queued to run as a task. Tasks are cooperative and queue-based, not preemptive. This means a long-running task can block the whole page — including user input and rendering.

Asynchronous operations — setTimeout, fetch, fs.readFile in Node.js — tell the host environment to do something in another thread. When the work is done, a task is posted to the event loop with the callback. This is how JavaScript gets asynchronous behaviour despite being single-threaded.

console.log("this is a script entry point");

document.body.onclick = () => {
  console.log("onclick");
};

  console.log("setTimeout callback log 1");
  console.log("setTimeout callback log 2");
}, 100);

// Output order:
// 1. "this is a script entry point"
// 2. "onclick" (when the user clicks)
// 3. "setTimeout callback log 1"
// 4. "setTimeout callback log 2"

// Asynchronous operations

  console.log("this happens later");
}, 100);

  console.log("data arrived");
});

Key Ideas

  • JavaScript is single-threaded, but the event loop handles concurrency.
  • Tasks are queued and run to completion — they cannot be interrupted.
  • Asynchronous operations post tasks to the event loop when they complete.
  • A long-running task blocks the entire page.

Strict Mode

"use strict" — opting into a stricter dialect of JavaScript

Strict mode is a way to opt into a stricter variant of JavaScript. Enable it by placing "use strict"; at the top of a script or function. Strict mode catches common mistakes, disables some sloppy behaviours, and throws errors for unsafe actions. It is enabled by default in ES6 modules and classes.

Strict mode prevents assigning to undeclared variables: a = 12; throws a ReferenceError instead of creating a global. It prevents deleting non-configurable properties: delete Object.prototype; throws a TypeError. It prevents extending non-extensible objects. It disallows duplicate parameter names. It changes the behaviour of arguments — it no longer reflects changes to parameters. It makes this undefined in standalone function calls.

Strict mode also affects block scoping of functions: in strict mode, functions declared inside a block are scoped to that block, like let. In non-strict mode, they are hoisted to the enclosing function. And strict mode disallows with statements.

Strict mode is not enabled by default in scripts, but is enabled in modules and classes. Use it in all new code. It catches bugs early and makes the language safer.

"use strict";

Data Manipulation

Formatting numbers, extracting extensions, and setting object properties by string

Formatting numbers as money is a common task. The quick way: num.toFixed(2).replace(/\d(?=(\d{3})+\.)/g, '$&,'). For more flexibility, a Number.prototype.format method lets you specify decimal places, group size, section delimiter, and decimal delimiter.

Extracting a file extension: filename.slice((filename.lastIndexOf('.') - 1 >>> 0) + 2). This handles files with no extension and files that start with a dot. A more robust version also handles full paths: split on / or \, take the last segment, find the last dot, and slice after it.

Setting an object property given its string name: assign(obj, 'foo.bar.foobar', 'Value') creates nested objects and assigns the value. This is useful for applying configuration objects or working with dotted keys.

// Format numbers as money

// "1,234,567.89"

  var re = '\\d(?=(\\d{' + (x || 3) + '})+' + (n > 0 ? '\\D' : '$') + ')',
      num = this.toFixed(Math.max(0, ~~n));
  return (c ? num.replace('.', c) : num).replace(new RegExp(re, 'g'), '$&' + (s || ','));
};

// Set object property given its string name

  if (typeof prop === 'string') {
    prop = prop.split('.');
  }
  if (prop.length > 1) {
    var e = prop.shift();
    assign(obj[e] = Object.prototype.toString.call(obj[e]) === '[object Object]' ? obj[e] : {},
           prop, value);
  } else {
    obj[prop[0]] = value;
  }
}

// obj == { foo: { bar: { foobar: 'Value' } } }

Binary Data

ArrayBuffers, TypedArrays, Blobs, and DataViews

JavaScript has two primary ways to represent binary data: ArrayBuffer / TypedArray and Blob. ArrayBuffers contain mutable, fixed-length binary data you can directly manipulate. Blobs contain immutable binary data accessible through the asynchronous File interface.

A TypedArray is a view into an ArrayBuffer. It coerces all assigned values to a given numeric type. Types include Uint8Array, Int8Array, Uint16Array, Int16Array, Uint32Array, Int32Array, Float32Array, and Float64Array. The DataView provides methods to read and write individual values from an ArrayBuffer with control over endianness.

Convert a Blob to an ArrayBuffer with FileReader.readAsArrayBuffer(). Convert an ArrayBuffer or TypedArray to a Blob with new Blob([array]). Convert a Base64 string to a TypedArray with atob() and a loop over the character codes.

To get the binary representation of an image file, read it as an ArrayBuffer, then use a DataView or Uint8Array to convert each byte to a binary string.

// Blob to ArrayBuffer (async)

fileReader.onload = function() {
  var array = this.result;
  console.log("Array contains", array.byteLength, "bytes.");
};
fileReader.readAsArrayBuffer(blob);

// ArrayBuffer to Blob
var array = new Uint8Array([0x04, 0x06, 0x07, 0x08]);
var blob2 = new Blob([array]);

// TypedArrays and DataViews
var buffer = new ArrayBuffer(2);
var view = new DataView(buffer);
view.setUint8(0, 0xFF);
view.setUint8(1, 0x01);
console.log(view.getUint16(0, false)); // 65281 (big-endian)
console.log(view.getUint16(0, true));  // 511 (little-endian)

// Base64 to TypedArray
var data = 'iVBORw0KGgoAAAANSUhEUgAAAAUAAAAFCAYAAACN';
var characters = atob(data);
var arr = new Uint8Array(characters.length);
for (var i = 0; i < characters.length; i++) {
  arr[i] = characters.charCodeAt(i);
}

// Binary representation of a file
function ArrayBufferToBinary(buffer) {
  var uint8 = new Uint8Array(buffer);
  return uint8.reduce((binary, uint8) => binary + uint8.toString(2), "");
}

Key Ideas

  • Use ArrayBuffer and TypedArray for mutable binary data.
  • Use Blob for immutable binary data accessed via FileReader.
  • DataView provides fine-grained control over bytes and endianness.
  • Convert between Blobs, ArrayBuffers, and Base64 strings as needed.

Template Literals

Backtick strings with interpolation and tags

Template literals are strings enclosed in backticks (`...`). They support multi-line strings and embedded expressions with ${expression}. const greeting = `Hello ${name}!`;. The expression is evaluated and inserted into the string.

Tagged templates let you control how a template literal is converted into a string. A tag function receives the constant parts of the template as an array and the evaluated substitutions as additional arguments. This is useful for escaping HTML, formatting numbers, or building domain-specific languages.

String.raw`...` is a built-in tag that returns the raw string, with backslash escapes left uninterpreted. String.raw`\n` returns a backslash followed by n, not a newline. The strings.raw property of a template literal provides the raw version of the strings array.

// Basic interpolation
const name = "John";
const score = 74;
console.log(`Game Over!
${name}'s score was ${score * 10}.`);
// "Game Over!
// John's score was 740."

// Tagged template
function settings(strings, ...substitutions) {
  const result = new Map();
  for (let i = 0; i < substitutions.length; i++) {
    result.set(strings[i].trim(), substitutions[i]);
  }
  return result;
}
const remoteConfiguration = settings`
  label ${'Content'}
  servers ${2 * 8 + 1}
  hostname ${location.hostname}
`;
// Map {"label" => "Content", "servers" => 17, "hostname" => "stackoverflow.com"}

// Raw strings
String.raw`\n`; // "\\n" (backslash + n)
`\n`;           // "\n" (newline)

const patternString = String.raw`Welcome, (\w+)!`;
const pattern = new RegExp(patternString);
pattern.exec("Welcome, John!");
// ["Welcome, John!", "John"]

// HTML templating
function HTML(strings, ...substitutions) {
  const escaped = substitutions.map(s =>
    [].concat(s).map(HTMLString.escape).join(''));
  const pieces = [];
  for (const i of strings.keys()) {
    pieces.push(strings[i], escaped[i] || '');
  }
  return new HTMLString(pieces.join(''));
}

Key Ideas

  • Template literals use backticks and support multi-line strings and ${} interpolation.
  • Tagged templates let a function control how the literal is assembled.
  • String.raw returns the raw string without escape interpretation.
  • Use tagged templates for HTML escaping, i18n, and DSLs.

Fetch

The modern Promise-based HTTP client

fetch(url, options) returns a Promise for a Response object. The Response contains status, headers, and a body that may still be loading. Use response.json(), response.text(), or response.blob() to read the body — each returns a Promise.

Scope

Closures, hoisting, var vs let, and the various forms of invocation

When a function is declared, variables in its enclosing scope are captured in its closure. Even after the outer function returns, the inner function can access and modify those variables. This is how "private" variables work in JavaScript: makeCounter() returns an object whose methods close over a private counter variable.

Hoisting moves variable and function declarations to the top of their scope. Variable assignments stay where they are. var declarations are hoisted and initialized to undefined; function declarations are fully hoisted. let and const declarations are hoisted but in a "temporal dead zone" — accessing them before declaration throws a ReferenceError.

var is function-scoped; let and const are block-scoped. This matters most inside loops and conditionals. In a loop with var, all closures see the same variable. With let, each iteration gets a new binding.

The value of this depends on how a function is invoked. Method invocation sets this to the object. Standalone invocation sets this to the global object (or undefined in strict mode). Constructor invocation sets this to the new object. bind sets this permanently. Arrow functions capture this lexically.

// Closure
function makeCounter() {
  var counter = 0;
  return {
    value: function () { return counter; },
    increment: function () { counter++; }
  };
}
var a = makeCounter();
var b = makeCounter();
a.increment();
console.log(a.value()); // 1
console.log(b.value()); // 0

// Hoisting
console.log(foo); // undefined
var foo = 42;
console.log(foo); // 42

// let and const TDZ
// console.log(bar); // ReferenceError
let bar = 42;

// var vs let in loops
for (var i = 0; i < 3; i++) {
  setTimeout(function() { console.log(i); }, 100); // 3, 3, 3
}
for (let j = 0; j < 3; j++) {
  setTimeout(function() { console.log(j); }, 100); // 0, 1, 2
}

// Invocation forms
var obj = {
  name: "Foo",
  print: function() { console.log(this.name); }
};
obj.print();           // "Foo" (method invocation)
var fn = obj.print;
fn();                  // undefined (standalone)

function Obj(name) { this.name = name; }
var inst = new Obj("Bar"); // constructor invocation

// bind
var bound = obj.print.bind(obj);
bound();               // "Foo"

// Arrow function
var arrow = () => this;
arrow() === window;    // true (in non-strict mode)

Key Ideas

  • Closures capture variables from the enclosing scope, even after the outer function returns.
  • var is function-scoped; let and const are block-scoped.
  • Hoisting moves declarations to the top of their scope; let/const are in a temporal dead zone.
  • this depends on invocation: method, standalone, constructor, bound, or arrow.

Modules

Private namespaces, explicit exports, and clean imports

ES6 modules let you split your code into separate files, each with its own private namespace. Top-level variables and functions do not pollute the global scope. To expose values, use the export keyword. To consume them, use import.

You can export named members individually: export const PI = 3.14; — export function doSomething() { ... }. Or you can export a list: export {doSomethingElse, MyClass};. Default exports represent the primary value of a module: export default function area(radius) { ... }. Import defaults without braces: import circleArea from './circle';.

Import named members with braces: import {doSomething, MyClass, PI} from './test';. Import everything into a namespace: import * as myModule from './test';. Import with aliases: import {longName as shortName} from './module';. Import for side effects only: import './polyfill';.

Modules are only supported natively in modern browsers and Node.js (with .mjs extension or "type": "module" in package.json). For older environments, use a bundler or transpiler. Modules are always in strict mode and have their own top-level scope.

// Defining a module (my-module.js)
export const PI = 3.14;
export function doSomething() {
  console.log('Hello from a module!');
}
function doSomethingElse() {
  console.log("Something else");
}
export {doSomethingElse};
export class MyClass {
  test() {}
}
function somethingPrivate() {
  console.log('TOP SECRET');
}

// Importing named members
import {doSomething, MyClass, PI} from './test';

// Importing an entire module
import * as myModule from './my-module.js';

// Importing with aliases
import {thisIsWayTooLongOfAName as shortName, PI} from 'module';

// Default export
// circle.js
export default function area(radius) {
  return PI * radius * radius;
}
// main.js
import circleArea from './circle';

// Import for side effects
import './test'; // runs top-level code

// Exporting multiple named members
const namedMember1 = ...;
const namedMember2 = ...;
export { namedMember1, namedMember2 };

Key Ideas

  • ES6 modules have their own scope; top-level variables are private by default.
  • Use export to expose values; use import to consume them.
  • Named exports use braces; default exports do not.
  • Use import * as ns to import everything into a namespace object.

Variable Coercion and Conversion

Converting between types — explicitly and implicitly

JavaScript tries to automatically convert variables to more appropriate types when used. This is called type coercion. It is usually advised to do conversions explicitly, but it's important to understand what happens implicitly. "1" + 5 is "15" (number converted to string); 1 - "5" is -4 (string converted to number); !0 is true (0 converted to boolean).

The Boolean() function converts any value to true or false. Empty strings, 0, NaN, null, and undefined are falsy; everything else is truthy. The !! double-negation is a shortcut: !!value is equivalent to Boolean(value).

The Number() function converts to a number. Number('0') is 0; Number('') is 0; Number('0x10') is 16; Number('10.5') is 10.5. The unary + operator is a faster shorthand: +'0' is 0. parseInt() and parseFloat() parse strings from the left and stop at the first invalid character.

String() converts any value to a string. String(0) is "0". The shorthand '' + 0 is equivalent. Arrays convert to comma-separated strings: [1, 2, 3].toString() is "1,2,3". Use join() for custom separators.

Boolean("true") === true;
Boolean("false") === true;
Boolean(-1) === true;
Boolean(1) === true;
Boolean(0) === false;
Boolean("") === false;
Boolean({}) === true;
Boolean([]) === true;

// Number conversion
Number('0') === 0;
Number('') === 0;
Number('0x10') === 16;
Number('10.5') === 10.5;
+'0' === 0;

// parseInt and parseFloat
parseInt('0', 10) === 0;
parseInt('10px', 10) === 10;
parseFloat("10.01") === 10.01;

// String conversion
String(0) === '0';
'' + 0 === '0';

// Array to string
["a", "b", "c"].join() === "a,b,c";
[1, 2, 3, 4].join(" + ") === "1 + 2 + 3 + 4";
["B", "o", "b"].join("") === "Bob";

// Float to integer
Math.floor(5.7); // 5
Math.ceil(5.3);  // 6
Math.round(3.2); // 3
Math.trunc(3.7); // 3

Key Ideas

  • JavaScript coerces types automatically — sometimes with surprising results.
  • Boolean() or !! converts to boolean; falsy values include 0, "", NaN, null, undefined.
  • Number(), parseInt(), and parseFloat() convert to numbers; the unary + is a shorthand.
  • String() or '' + value converts to string; arrays join with commas by default.

Destructuring Assignment

Unpacking values from objects and arrays into variables

Destructuring is a pattern-matching technique that lets you bind a group of variables to a corresponding set of values. For objects: let { name, age } = person; creates variables name and age from the person object. For arrays: const [a, b, c] = myArr; creates variables for each element.

You can rename variables: let { name: firstName } = person; creates firstName bound to person.name. You can provide default values: let { phone = '123-456-789' } = person;. You can nest destructuring: let { a: { c: x }, b: z } = obj;.

Destructuring works in function arguments: function greeting({name, profession}) { ... }. It works with arrays in objects and objects in arrays. It works with the rest operator: const [a, ...rest] = [1, 2, 3]; gives a = 1, rest = [2, 3]. And it works with default values: const [a = 5, b = 10] = [];.

// Object destructuring
let person = { name: 'Bob', age: 25 };
let { name, age } = person;
// name === 'Bob', age === 25

// Renaming
let { name: firstName } = person;
// firstName === 'Bob'

// Default values
let { phone = '123-456-789' } = person;
// phone === '123-456-789'

// Renaming with default values
let { phone: p = '123-456-789' } = person;
// p === '123-456-789'

// Nested destructuring
var obj = { a: { c: 1, d: 3 }, b: 2 };
var { a: { c: x, d: y }, b: z } = obj;
// x === 1, y === 3, z === 2

// Array destructuring
const myArr = ['one', 'two', 'three'];
const [a, b, c] = myArr;
// a === 'one', b === 'two', c === 'three'

// Swap variables
var x1 = 1, x2 = 3;
[x1, x2] = [x2, x1];
// x1 === 3, x2 === 1

// Skip elements
const [first, , third] = [1, 2, 3];
// first === 1, third === 3

// Rest operator
const [first2, ...rest] = [1, 2, 3, 4];
// first2 === 1, rest === [2, 3, 4]

// Function arguments
let user = { name: 'Jill', age: 33, profession: 'Pilot' };
function greeting({name, profession}) {
  console.log(`Hello, ${name} the ${profession}`);
}
greeting(user); // "Hello, Jill the Pilot"

// Array function arguments
let parts = ["Hello", "World!"];
function greeting2([first, second]) {
  console.log(`${first} ${second}`);
}
greeting2(parts); // "Hello World!"

Key Ideas

  • Destructuring binds variables to values from objects or arrays.
  • You can rename variables and provide default values.
  • Destructuring works in function arguments, nested structures, and with the rest operator.

Arrow Functions

Concise syntax, lexical this, and implicit return

Arrow functions are a concise way of writing anonymous functions. (arguments) => expression. If the body is a single expression, the return is implicit: item => item + 1. If the body is a block, use braces and an explicit return. Object literals in implicit-return position must be wrapped in parentheses: () => ({foo: 1}).

Arrow functions lexically bind this. They take their this from the enclosing scope, regardless of how they are called. This makes them ideal for callbacks that need to access the outer this. They do not have their own arguments object; use rest parameters instead. They cannot be used as constructors with new.

Arrow functions are not a complete replacement for regular functions. Use regular functions for methods, constructors, and any function that needs its own this or arguments. Use arrow functions for short callbacks and transformations.

// Basic arrow function
const add = (a, b) => a + b;
add(2, 3); // 5

// Single parameter — no parentheses
const double = x => x * 2;

// No parameters — empty parentheses
const greet = () => "Hello";

// Block body — explicit return
const square = x => {
  return x * x;
};

// Returning an object literal
const makeObj = () => ({ foo: 1 });
makeObj(); // {foo: 1}

// Lexical this
class Cow {
  constructor() {
    this.sound = "moo";
  }
  makeSoundLater() {
    setTimeout(() => console.log(this.sound), 1000);
  }
}
const betsy = new Cow();
betsy.makeSoundLater(); // "moo"

// No arguments object
const arguments = [true];
const foo = x => console.log(arguments[0]);
foo(false); // true (uses outer arguments)

// Rest parameters instead
const foo2 = (...args) => console.log(args[0]);
foo2(false); // false

// Not a constructor
const bar = () => {
  return 'bar';
};
// new bar(); // TypeError: bar is not a constructor

Key Ideas

  • Arrow functions use => and have an implicit return for single expressions.
  • this is lexically bound — it inherits from the enclosing scope.
  • Arrow functions have no arguments object; use rest parameters instead.
  • Arrow functions cannot be used with new.

requestAnimationFrame

Smooth, efficient animations with the browser's render loop

window.requestAnimationFrame(callback) schedules a function to run before the next repaint. It returns an ID that can be passed to cancelAnimationFrame to cancel the request. The callback receives a timestamp — the time elapsed since the page started loading.

Using requestAnimationFrame is more efficient than setTimeout or setInterval for animations. The browser can optimize the timing, pause when the tab is not visible, and sync with the display refresh rate (typically 60 Hz).

For compatibility with older browsers, use a polyfill that falls back to setTimeout(callback, 1000 / 60). But note that the fallback does not return an ID compatible with cancelAnimationFrame.

// Fade in over 2 seconds
var FADE_DURATION = 2.0 * 1000;
var startTime = -1.0;

function render(currTime) {
  var head1 = document.getElementsByTagName('h1')[0];
  var opacity = (currTime / FADE_DURATION);
  head1.style.opacity = opacity;
}

function eachFrame() {
  var timeRunning = (new Date()).getTime() - startTime;
  if (startTime < 0) {
    startTime = (new Date()).getTime();
    render(0.0);
  } else if (timeRunning < FADE_DURATION) {
    render(timeRunning);
  } else {
    return;
  }
  window.requestAnimationFrame(eachFrame);
}

window.requestAnimationFrame(eachFrame);

// Polyfill

  return window.requestAnimationFrame ||
         window.webkitRequestAnimationFrame ||
         window.mozRequestAnimationFrame ||
         function(callback) {
           window.setTimeout(callback, 1000 / 60);
         };
})();

function draw(timestamp) {
  start();
}
function pause() {
  cancelAnimationFrame(requestId);
}
function start() {
  requestId = requestAnimationFrame(draw);
}
start();
setTimeout(pause, 1000);

  • requestAnimationFrame schedules a callback before the next repaint.

Creational Design Patterns

Factories, modules, prototypes, singletons, and abstract factories

The Factory Function returns a new object. Unlike a constructor, it doesn't need new. function cowFactory(name) { return { name: name, talk: function() { ... } }; }. Private variables and methods can be defined outside the returned object, keeping the implementation encapsulated.

The Module Pattern encapsulates private members and exposes a public API via an IIFE. var Module = (function() { var privateData = 1; return { getPrivateData: function() { return privateData; } }; })();. The Revealing Module Pattern defines all members inside the closure and returns an object literal with references to them.

The Prototype Pattern creates objects that inherit from a shared prototype. Welcome.prototype.sayHello = function() { ... }; — all instances share the method. Subclasses inherit via Object.create and call the parent constructor with Parent.call(this, ...). The Singleton Pattern restricts instantiation to one object. The Abstract Factory Pattern defines an interface for creating families of related objects.

// Factory function
function cowFactory(name) {
  function formalName() {
    return name + ' the cow';
  }
  return {
    talk: function() {
      console.log('Moo, my name is ' + formalName());
    }
  };
}
var daisy = cowFactory('Daisy');
daisy.talk(); // "Moo, my name is Daisy the cow"

// Module pattern
var Module = (function() {
  var privateData = 1;
  var api = {
    getPrivateData: function() { return privateData; },
    getDoublePrivateData: function() { return api.getPrivateData() * 2; }
  };
  return api;
})();

// Prototype pattern
function Welcome(name) {
  this.name = name;
}
Welcome.prototype.sayHello = function() {
  return 'Hello, ' + this.name + '!';
};
var welcome = new Welcome('John');
welcome.sayHello(); // "Hello, John!"

// Inheriting with prototype
function RoomService(name, order) {
  Welcome.call(this, name);
  this.order = order;
}
RoomService.prototype = Object.create(Welcome.prototype);
RoomService.prototype.constructor = RoomService;

// Singleton
var Singleton = (function() {
  var instance;
  function createInstance() {
    return { publicMethod: function() {} };
  }
  return {
    getInstance: function() {
      if (!instance) {
        instance = createInstance();
      }
      return instance;
    }
  };
})();

// Abstract factory
function Car() { this.name = "Car"; this.wheels = 4; }
function Truck() { this.name = "Truck"; this.wheels = 6; }
const vehicleFactory = {
  createVehicle: function(type) {
    switch (type.toLowerCase()) {
      case "car": return new Car();
      case "truck": return new Truck();
      default: return null;
    }
  }
};

Key Ideas

  • Factory functions return objects without new, and can encapsulate private state.
  • The Module Pattern uses IIFEs to create private scope and a public API.
  • The Prototype Pattern shares methods via the prototype; the Singleton restricts instantiation.
  • The Abstract Factory creates families of related objects without specifying concrete classes.

Detecting Browser

Feature detection, user-agent sniffing, and library-based detection

Browser detection is the practice of identifying the browser and its capabilities so that your code can adapt. There are three main approaches: feature detection, user-agent sniffing, and library-based detection. Each has strengths and weaknesses.

Feature detection checks for the existence of a browser-specific API. if ('geolocation' in navigator) { ... }. This is more reliable than user-agent sniffing because it tests what the browser can actually do, not what it claims to be. But it is not guaranteed to be future-proof — a browser may implement a feature differently.

User-agent sniffing parses navigator.userAgent to determine the browser name and version. This is easily spoofed and quickly becomes outdated as browsers evolve. Use it only as a last resort.

Library-based detection uses a library like Bowser to handle the complexity. if (bowser.msie && bowser.version >= 6) { ... }. This is convenient but adds a dependency. For most projects, feature detection is the best approach.

Symbols

Unique, immutable primitive values for property keys

Symbol is a new primitive type in ES6. Symbols are unique and immutable, and are used primarily as property keys. Even if two symbols have the same description, they are different values. const MY_PROP_KEY = Symbol(); — obj[MY_PROP_KEY] = "ABC". No other property key can collide with it.

Symbols are useful for creating private or hidden properties on objects. They don't appear in for...in loops or Object.keys(), though they can be retrieved with Object.getOwnPropertySymbols().

Symbol.for('key') creates a global, shared symbol. The first call with a given key creates the symbol and registers it; subsequent calls return the same symbol. Symbol.for('A') === Symbol.for('A') is true, but Symbol('A') === Symbol('A') is false.

Symbols are not automatically converted to strings. Symbol('Apple') + '' throws a TypeError. Use .toString() or String(symbol) to convert.

// Creating a symbol
const MY_PROP_KEY = Symbol();
const obj = {};
obj[MY_PROP_KEY] = "ABC";
console.log(obj[MY_PROP_KEY]); // "ABC"

// Named symbols
const APPLE = Symbol('Apple');
const BANANA = Symbol('Banana');
const GRAPE = Symbol('Grape');
APPLE === BANANA; // false

// Global symbols
let a = Symbol.for('A');
a === Symbol.for('A'); // true
a === Symbol('A');    // false

// Converting to string
const sym = Symbol('Apple');
sym.toString();       // "Symbol(Apple)"
String(sym);          // "Symbol(Apple)"

// Not in for...in
const obj2 = { [Symbol('hidden')]: 1, visible: 2 };
for (let key in obj2) { console.log(key); } // only "visible"
Object.keys(obj2); // ["visible"]
Object.getOwnPropertySymbols(obj2); // [Symbol(hidden)]

Key Ideas

  • Symbols are unique, immutable primitive values, used as property keys.
  • Symbol.for(key) creates a global, shared symbol; Symbol(key) creates a unique symbol.
  • Symbols don't appear in for...in or Object.keys — they are hidden by default.
  • Convert to string with .toString() or String().

Transpiling

Writing modern JavaScript that runs on older browsers

Transpiling is the process of translating source code from one language (or language version) to another. In JavaScript, it usually means compiling modern ES6+ syntax down to ES5 for compatibility with older browsers. The most prominent transpiler is Babel.

Babel takes ES6+ code and outputs equivalent ES5 code. Arrow functions become regular functions; classes become constructor functions and prototypes; let and const become var with appropriate scope handling; template literals become string concatenation. The output is functionally equivalent, but runs in older environments.

Other compile-to-JavaScript languages include TypeScript, CoffeeScript, and Elm. These add their own features on top of JavaScript. TypeScript adds static typing; CoffeeScript adds a cleaner syntax; Elm is purely functional and compiled to JavaScript.

To use Babel, install it with npm, configure it with a .babelrc file, and run it on your source files. Tools like Webpack and Gulp can integrate Babel into your build process.

Automatic Semicolon Insertion

When JavaScript inserts semicolons for you — and when it doesn't

JavaScript has a feature called Automatic Semicolon Insertion (ASI). The parser tries to insert semicolons when it encounters an invalid token or a line terminator. This can prevent errors but can also cause subtle bugs — especially with return statements.

The classic pitfall: return followed by a newline. return\n{ foo: 'foo' }; is interpreted as return; followed by a block statement. The function returns undefined. To return an object literal, put the opening brace on the same line as return.

ASI rules: insert a semicolon if the next token cannot be parsed, if the next token is }, or if the next token is a restricted token (like ++ or --) separated by a line terminator. But never insert a semicolon if it would create an empty statement or a for loop header.

To avoid ASI bugs, use semicolons consistently. Most style guides recommend them. The extra characters are worth the clarity.

// This returns undefined
function foo() {
  return
  {
    foo: 'foo'
  };
}
foo(); // undefined

// This returns the object
function properFoo() {
  return {
    foo: 'foo'
  };
}
properFoo(); // { foo: 'foo' }

// ASI example
a = b
++c
// is transformed to:
a = b;
++c;

x
++
y
// is transformed to:
x;
++y;

// Array indexing
console.log("Hello, World")
[1,2,3].join()
// is transformed to:
console.log("Hello, World")[(1, 2, 3)].join();

// Return statement
return
"something";
// is transformed to
return;
"something";

Key Ideas

  • ASI inserts semicolons at line breaks when the parser can't continue.
  • Place the opening brace on the same line as return, if, and functions to avoid silent errors.
  • Be careful with ++, --, and array indexing at the start of a line.
  • Use semicolons consistently to avoid ASI surprises.

Geolocation

Finding the user's location — with permission

The Geolocation API lets you retrieve the user's location with their permission. Check for support with if (navigator.geolocation) { ... }. The success callback receives a Position object with coords.latitude, coords.longitude, coords.accuracy, and optionally coords.altitude, coords.heading, and coords.speed. The error callback receives a PositionError with a code of 1 (permission denied), 2 (position unavailable), or 3 (timeout).

To stop watching, use navigator.geolocation.clearWatch(watchId). Location tracking over time can be very sensitive — explain to the user ahead of time why you're requesting this permission and how you'll use the data.

// Check for support
if (navigator.geolocation) {

var geolocationSuccess = function(pos) {

};

// Error callback
var geolocationFailure = function(err) {
  console.log("ERROR (" + err.code + "): " + err.message);
};

var watchId = navigator.geolocation.watchPosition(updateLocation, geolocationFailure);

Modularization Techniques

ES6 modules, UMD, IIFE, AMD, and CommonJS

Modularization is the practice of breaking code into self-contained, reusable pieces. JavaScript has several module systems, each with its own strengths. ES6 modules are the modern standard: import and export, with private scope per file. UMD (Universal Module Definition) works in many environments — AMD, CommonJS, and browser globals.

IIFE (Immediately Invoked Function Expression) creates private scope without a module system: (function() { var private = 1; return { get: function() { return private; } }; })();. AMD (Asynchronous Module Definition) uses define() and is designed for browsers with async loading. CommonJS uses require() and module.exports, and is used by Node.js.

Each system has trade-offs. ES6 modules are static and tree-shakeable; CommonJS is dynamic and synchronous; AMD is asynchronous; UMD works everywhere. For new code, ES6 modules are the best choice. For older environments, transpile ES6 modules to CommonJS or UMD.

// ES6 modules
export function greet(name) {
  console.log("Hello %s!", name);
}
export class MyClass {
  test() {}
}

// UMD
(function (root, factory) {
  if (typeof define === 'function' && define.amd) {
    define(['exports', 'b'], factory);
  } else if (typeof exports === 'object' && typeof exports.nodeName !== 'string') {
    factory(exports, require('b'));
  } else {
    factory((root.commonJsStrict = {}), root.b);
  }
}(this, function (exports, b) {
  exports.action = function () {};
}));

// IIFE
var Module = (function() {
  var privateData = 1;
  return {
    getPrivateData: function() {
      return privateData;
    }
  };
})();
Module.getPrivateData(); // 1

// AMD
define("myModule", ["jquery", "lodash"], function($, _) {
  var myModule = {};
  myModule.version = 1;
  myModule.moduleMethod = function() {
    return privateFn(windowTitle);
  };
  return myModule;
});

// CommonJS (Node.js)
var fs = require("fs"),
    _ = require("lodash");
var myPrivateFn = function(param) {
  return "Here's what you said: " + param;
};
exports.myMethod = function(param) {
  return myPrivateFn(param);
};
module.exports = function() {
  return "Hello!";
};

Key Ideas

  • ES6 modules are the modern standard, using import and export.
  • UMD works in AMD, CommonJS, and browser-global environments.
  • IIFEs create private scope without a module system.
  • AMD is asynchronous; CommonJS is synchronous and used by Node.js.

Proxy

Intercepting fundamental operations on objects

A Proxy wraps an object and intercepts operations on it — property lookup, assignment, deletion, function calls, and more. new Proxy(target, handler) creates a proxy. The handler defines "traps" — methods that are called when the corresponding operation occurs. If a trap is not defined, the operation is performed on the target as if there were no proxy.

The get trap intercepts property lookup. let handler = { get(target, property) { ... } };. The set trap intercepts assignment: set(target, prop, value) { ... }. Other traps include has, deleteProperty, apply, construct, getPrototypeOf, setPrototypeOf, defineProperty, ownKeys, and more.

Proxies are useful for validation, logging, virtualization, and metaprogramming. They are powerful but also complex — and their performance overhead can be significant. Use them carefully.

// Proxying property lookup
let handler = {
  get(target, property) {
    if (!Reflect.has(target, property)) {
      return { value: undefined, type: 'undefined' };
    }
    let value = Reflect.get(target, property);
    return { value: value, type: typeof value };
  }
};
let proxied = new Proxy({foo: 'bar'}, handler);
console.log(proxied.foo); // { value: "bar", type: "string" }

// Simple proxy with set trap
let object = {};
let handler2 = {
  set(target, prop, value) {
    if ('string' === typeof value) {
      target[prop] = value + " went through proxy";
    }
  }
};
let proxied2 = new Proxy(object, handler2);
proxied2.example = "ExampleValue";
console.log(object); // { example: "ExampleValue went through proxy" }

Key Ideas

  • A Proxy wraps an object and intercepts operations via traps.
  • Common traps include get, set, has, deleteProperty, apply, and construct.
  • Use Reflect to forward operations to the target.
  • Proxies enable validation, logging, and metaprogramming — but add complexity.

// Sending a message

WeakMap

Key-value pairs with weakly-referenced keys

A WeakMap is a collection of key-value pairs where the keys are weakly referenced. Unlike a regular Map, the keys must be objects, and if there are no other references to a key, the entire entry can be garbage-collected. This makes WeakMaps useful for storing private data or metadata associated with objects without preventing those objects from being collected.

Use weakmap.set(key, value), weakmap.get(key), weakmap.has(key), and weakmap.delete(key). WeakMaps do not have a .size property and cannot be iterated — because their keys may be garbage-collected at any time. This is what makes them "weak."

WeakMaps are ideal for private data in classes, since they don't create strong references to the key objects. When the key object is no longer needed, the WeakMap entry is automatically removed.

// Creating a WeakMap
const o1 = {a: 1, b: 2},
      o2 = {};
const weakmap = new WeakMap([[o1, true], [o2, o1]]);

// Getting a value
const obj1 = {}, obj2 = {};
const weakmap2 = new WeakMap([[obj1, 7]]);
console.log(weakmap2.get(obj1)); // 7
console.log(weakmap2.get(obj2)); // undefined

// Setting a value (chainable)
weakmap2.set(obj1, 1).set(obj2, 2);

// Checking existence
weakmap2.has(obj1); // true
weakmap2.has(obj2); // true

// Removing
weakmap2.delete(obj1); // true
weakmap2.has(obj1);    // false

    topSecret.set(this, secret);

  }
}

  • WeakMap keys must be objects; they are weakly referenced.
  • WeakMaps are not iterable and have no .size property.
  • Use WeakMaps for private data and metadata associated with objects.
  • When the key object is garbage-collected, the WeakMap entry is removed.

WeakSet

Collections of weakly-held objects

A WeakSet is a collection of objects held weakly. Unlike a regular Set, a WeakSet can only contain objects — not primitive values. And references to the objects are weak, meaning if there are no other references to an object stored in a WeakSet, it can be garbage-collected.

Use weakset.add(obj), weakset.has(obj), and weakset.delete(obj). Like WeakMap, WeakSet is not iterable and has no .size property. The .add() method is chainable.

WeakSets are useful for tagging objects — marking them as "processed" or "seen" — without preventing garbage collection. If an object is only referenced by a WeakSet, it can be collected, and the WeakSet entry disappears with it.

// Creating a WeakSet
const obj1 = {}, obj2 = {};
const weakset = new WeakSet([obj1, obj2]);

// Adding a value
weakset.add(obj1).add(obj2);

// Checking existence
weakset.has(obj1); // true
weakset.has(obj2); // true

// Removing a value
weakset.delete(obj1); // true
weakset.delete(obj2); // false (if already removed)

// Use case: tracking processed objects
const processed = new WeakSet();
function process(obj) {
  if (processed.has(obj)) return;
  processed.add(obj);
  // do processing
}

Key Ideas

  • WeakSet stores objects with weak references — no primitive values.
  • WeakSets are not iterable and have no .size property.
  • Use WeakSets for tagging or tracking objects without preventing garbage collection.
  • Chainable .add() makes it easy to tag multiple objects.

Escape Sequences

Representing special characters in strings and regular expressions

Escape sequences represent characters that are hard to type or that have special meaning in strings and regular expressions. They start with a backslash \. Common single-character escapes include \n (line feed), \t (tab), \r (carriage return), \f (form feed), and \v (vertical tab). \\, \', and \" escape backslash, single quote, and double quote.

Hexadecimal escapes use \x followed by two hex digits: \xa0 is a non-breaking space. Four-digit Unicode escapes use \u followed by four hex digits: \u2192 is a right arrow. ES6 adds curly-brace Unicode escapes for code points beyond 2¹⁶ − 1: \u{1f440} is the eyes emoji.

Octal escapes (\105) are deprecated and disallowed in strict mode. Control escapes (\cA through \cZ) are only valid in regular expressions. They represent control characters U+0001 through U+001A.

// Line feed

// Unicode escapes
var arrow = "A \u2192 B"; // "A → B"

// ES6 curly-brace Unicode
alert("Look! \u{1f440}"); // "Look! 👀"

// Escape quotes
var single = 'L\'albero means tree in Italian';
var double = "I feel \"high!\"";

// Regular expression escapes

Key Ideas

  • Escape sequences start with \ and represent special characters.
  • \n, \t, \r, \f, and \v are single-character escapes.

Behavioral Design Patterns

Observer, Mediator, Command, and Iterator

The Observer Pattern is used for event handling and delegation. A subject maintains a collection of observers and notifies them when an event occurs. addEventListener is a built-in example. Custom observers implement registerObserver, unregisterObserver, and notifyObservers.

The Mediator Pattern is a communication hub among different modules. Instead of modules talking to each other directly, they talk to a mediator, which routes messages. This reduces coupling and increases loose coupling and portability.

The Command Pattern encapsulates a method call — the method name, parameters, and state — as an object. This lets you defer execution, queue commands, or undo operations. The pattern has three components: the command message (the command itself), the invoker (which executes it), and the receiver (the target of the command).

The Iterator Pattern provides a simple method for selecting, sequentially, the next item in a collection. In ES6, iterators return {value, done} objects and implement a Symbol.iterator method. Generators are a convenient way to create iterators.

// Observer pattern
function Subject() {
  this.observers = [];
  this.registerObserver = function(observer) {
    if (this.observers.indexOf(observer) === -1) {
      this.observers.push(observer);
    }
  };
  this.notifyObservers = function(message) {
    this.observers.forEach(function(observer) {
      observer.notify(message);
    });
  };
}

// Mediator pattern
var Chatroom = function() {
  var participants = {};
  return {
    register: function(participant) {
      participants[participant.name] = participant;
      participant.chatroom = this;
    },
    send: function(message, from) {
      for (key in participants) {
        if (participants[key] !== from) {
          participants[key].receive(message, from);
        }
      }
    }
  };
};

// Command pattern
var aCommand = new Array();
aCommand.push(new Instructions().DoThis);
aCommand.push("String Argument");
aCommand.push(777);
aCommand.Execute();

// Iterator pattern
class BeverageForPizza {
  constructor(beverageList) {
    this.beverageList = beverageList;
    this.pointer = 0;
  }
  next() {
    return this.beverageList[this.pointer++];
  }
}
var withPepperoni = new BeverageForPizza(["Cola", "Water", "Beer"]);

withPepperoni.next(); // "Water"
withPepperoni.next(); // "Beer"

Key Ideas

  • Observer: a subject notifies a list of observers when events occur.
  • Mediator: a central hub routes communication between modules.
  • Command: encapsulate a method call as an object to defer, queue, or undo it.
  • Iterator: provide a sequential access method for a collection.

An async function returns a Promise. Inside an async function, the await keyword pauses execution until a Promise settles, then returns its resolved value. Errors are thrown as exceptions, which can be caught with try/catch. This makes asynchronous code look and feel synchronous.

async function getJSON(url) { try { const response = await fetch(url); return await response.json(); } catch (err) { console.error(err.message); } }. The function returns a Promise that resolves with the JSON data, or rejects with the error. Callers can use .then() or await.

Await has operator precedence issues: await getUnicorn().getSize() is parsed as await (getUnicorn().getSize()), which tries to call getSize on the Promise. Use parentheses: (await getUnicorn()).getSize().

Iterator in Async Callback

Variable capture bugs, and how to avoid them

When using asynchronous callbacks inside a loop, the loop variable is shared across all iterations. If the callback runs after the loop has finished, it sees the final value of the variable — not the value at the time the callback was scheduled. This is a common source of bugs.

The classic example: for (var key in pipeline) { fs.stat(pipeline[key].path, function(err, stats) { if (err) { delete pipeline[key]; return; } pipeline[key].count++; }); }. The var key is shared; when the callbacks run, key may have been incremented past the intended element.

The fix: create a new scope for each iteration. Use let instead of var (ES6), or wrap the loop body in a function that captures the current value: var processOneFile = function(key) { fs.stat(...) };. With let, each iteration gets its own binding.

// Erroneous code — shared key
var pipeline = {};
for (var key in pipeline) {
  fs.stat(pipeline[key].path, function(err, stats) {
    if (err) {
      delete pipeline[key]; // key may have changed
      return;
    }
    pipeline[key].count++;
  });
}

// Correct: wrap in a function
var processOneFile = function(key) {
  fs.stat(pipeline[key].path, function(err, stats) {
    if (err) {
      delete pipeline[key];
      return;
    }
    pipeline[key].count++;
  });
};
for (var key in pipeline) {
  processOneFile(key);
}

// Correct: use let
for (let key in pipeline) {
  fs.stat(pipeline[key].path, function(err, stats) {
    if (err) {
      delete pipeline[key];
      return;
    }
    pipeline[key].count++;
  });
}

Key Ideas

  • Callbacks inside loops can capture the wrong value of the loop variable.
  • Use let instead of var to create a new binding per iteration.
  • Wrap the loop body in a function to capture the current value.
  • This pitfall is especially common with asynchronous callbacks.

Tail Call Optimization

Recursion without growing the stack

Tail Call Optimization (TCO) is a feature of some JavaScript engines that eliminates the stack growth of recursive calls. When a function's return value is the result of another function call, and that call is in "tail position," the engine can reuse the current stack frame instead of creating a new one.

Without TCO, recursive functions have a limited depth. Each call pushes a new frame onto the stack; eventually, the stack overflows. With TCO, the stack doesn't grow — recursion can continue indefinitely.

TCO is only available in strict mode, and browser support is inconsistent. It is not implemented in most browsers. The specification allows it, but engines may not implement it, because it can break web compatibility (e.g., by changing the shape of stack traces).

"use strict";

// Without TCO: stack grows
function a() {
  return b();
}
function b() {
  return 1;
}
a();

// With TCO: a()'s frame is reused
function indexOf(array, predicate, i = 0) {
  if (0 <= i && i < array.length) {
    if (predicate(array[i])) { return i; }
    return indexOf(array, predicate, i + 1); // tail call
  }
}
indexOf([1,2,3,4,5,6,7], x => x === 5); // 4

Key Ideas

  • TCO eliminates stack growth for recursive calls in tail position.
  • Only available in strict mode, and browser support is inconsistent.
  • Without TCO, recursion has a limited depth.
  • Use TCO when available for infinite recursion or deep recursion.

Bitwise Operators — Real World Examples

Swapping, multiplying, and parity checking with bits

Bitwise operators are fast and useful for low-level tasks. Swapping two integers with XOR: a = a ^ b; b = a ^ b; a = a ^ b;. This works because XOR is its own inverse — (a ^ b) ^ b === a. It avoids the need for a temporary variable.

Faster multiplication or division by powers of 2: x << n multiplies by 2^n; x >> n divides by 2^n (floored). 13 << 6 is 13 * 64 = 832. 1000 >> 4 is 1000 / 16 = 62. This is not necessarily faster in modern JavaScript engines, but it is a useful idiom.

Number's parity detection: if (n & 1) { console.log("ODD"); } else { console.log("EVEN"); }. This is faster and more direct than n % 2 == 0. The bitwise AND with 1 checks the least significant bit — 0 for even, 1 for odd.

a = a ^ b;
b = a ^ b;
a = a ^ b;
console.log("a = " + a + "; b = " + b); // a = 22; b = 11

// Faster multiplication by powers of 2

// Faster division by powers of 2
1000 / (2 ** 4); // 62.5
1000 >> 4;       // 62

// Negative numbers

-80 >> 3;       // -10

// Parity detection

  console.log("ODD!");
} else {
  console.log("EVEN!");
}

Tilde ~

Bitwise NOT, double tilde, and shorthand tricks

The tilde operator ~ flips every bit in its operand. For a number n, ~n is equal to -(n + 1). ~3 is -4; ~-2 is 1. This is not the same as negation — it's a bitwise operation.

The double tilde ~~ applies ~ twice. For integers, this is a no-op: ~~3 === 3. For decimals, it truncates toward zero: ~~3.5 === 3; ~~-3.5 === -3. This is a shorthand for Math.trunc (for numbers within the 32-bit range).

The tilde operator is also used as a shorthand for indexOf checks: if (~array.indexOf(item)) is true if the item exists (because indexOf returns -1 for not-found, and ~-1 is 0, which is falsy). This is a common but less-readable idiom.

// Bitwise NOT

~-2;     // 1
~-1;     // 0
~0;      // -1
~1;      // -2
~2;      // -3

// Double tilde — truncation
~~3.5;   // 3
~~-3.5;  // -3
~~-2.5;  // -2
~~1.5;   // 1

// Converting non-numeric values
~~"-2";   // -2
~~"1";    // 1
~~"0";    // 0
~~"true"; // 0
~~"false"; // 0
~~true;   // 1
~~false;  // 0
~~"";     // 0

// Shorthand for indexOf

// or

// both check if 'a' exists

Key Ideas

  • ~n is bitwise NOT; ~n === -(n + 1).
  • ~~n truncates toward zero (for numbers in the 32-bit range).
  • ~~ converts non-numeric values to numbers, with true as 1 and false as 0.

Fluent API

A Fluent API is a consumer-oriented API that reads like a domain-specific language. It achieves this through method chaining and careful naming. The goal is to make the code more readable, almost like prose.

Fluent APIs are often used in libraries like jQuery and testing frameworks like Chai. They improve readability for complex operations. But they can also make debugging harder — chains obscure intermediate values. Use them where they clarify the domain, not as a universal style.

  constructor(header, paragraphs) {
    this.header = header;

  toHtml() {
    return `<section><h2>${this.header}</h2>${this.paragraphs.map(p => p.toHtml()).join('')}</section>`;

Web Cryptography API

The Web Cryptography API provides cryptographic operations in the browser. crypto.subtle.digest('SHA-256', input) returns a Promise for an ArrayBuffer hash. crypto.getRandomValues(array) fills a TypedArray with cryptographically random values. crypto.subtle.generateKey() generates key pairs.

To hash a string, encode it as an ArrayBuffer with TextEncoder, then call crypto.subtle.digest. Convert the resulting ArrayBuffer to a hex string with a DataView or Uint8Array. Supported algorithms include SHA-1, SHA-256, SHA-384, and SHA-512.

    hexstr += '0123456789abcdef'[(b & 0xf0) >> 4];
    hexstr += '0123456789abcdef'[(b & 0x0f)];
  }
  console.log(hexstr);
}).catch(function(err) {
  console.error(err);
});

Security Issues

Cross-site scripting, eval injection, and how to prevent them

Cross-site scripting (XSS) is one of the most common web vulnerabilities. It occurs when user input is included in a page without proper escaping, allowing an attacker to inject scripts. There are three main types: reflected XSS, persistent XSS, and XSS from JavaScript string literals.

Reflected XSS occurs when user input is immediately returned in the response without escaping. For example, a search page that echoes the query: <div>Your search (<b> + searchQuery + </b>) didn't match anything.</div>. If the query is <script>alert(1)</script>, the script runs. Mitigation: escape all angle brackets, or don't return the query at all.

Persistent XSS occurs when user input is stored and later displayed without escaping. A profile description containing <script>...</script> runs for every visitor. Mitigation: escape before rendering, store plain text and use innerText, or add a Content Security Policy.

Eval injection occurs when user input is passed to eval(). Never use eval with untrusted data. Use JSON.parse instead of eval for parsing JSON. Properly escape " and \ in user data if you must build JSON strings by hand.

// Reflected XSS
if (!searchResults) {
  webPage += "<div>Your search (<b>" + searchQuery + "</b>), didn't match anything.</div>";
}

// If searchQuery is "<script>alert(1)</script>", the script runs

// Persistent XSS
if (viewedPerson.profile.description) {
  page += "<div>" + viewedPerson.profile.description + "</div>";
}

// Mitigation: escape angle brackets
function escapeHtml(text) {
  return text
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;')
    .replace(/'/g, '&#39;');
}

// Eval injection
var data = eval("(" + resp + ")"); // dangerous!
// Mitigation: use JSON.parse
var data = JSON.parse(resp);

// JSON string literals
// Bad: dynamically building script
for (var i = 0; i < messages.length; i++) {
  script += "addMessage(\"" + messages[i] + "\");";
}
// Good: pass through JSON.stringify
script += "addMessage(" + JSON.stringify(message) + ");";

Key Ideas

  • XSS occurs when user input is included in a page without escaping.
  • Reflected XSS returns input immediately; persistent XSS stores it and displays it later.
  • Escape angle brackets, quotes, and ampersands; use innerText for plain text.
  • Never use eval with untrusted data; use JSON.parse instead.

Same Origin Policy & Cross-Origin Communication

Protecting resources across origins — and how to work around the restriction

The Same-Origin Policy prevents scripts from accessing resources from a different origin. Two URLs have the same origin if they share protocol, hostname, and port. http://example.com/page1 and http://example.com/page2 share an origin; http://example.com and https://example.com do not (different protocols).

Cross-origin communication can be achieved with window.postMessage (safe for iframes) and CORS (Cross-Origin Resource Sharing) for AJAX. JSONP is a legacy workaround that loads external data via a script tag with a callback query parameter.

CORS is the modern approach: the server sets an Access-Control-Allow-Origin header indicating which origins are allowed. The browser checks this header and enforces the restriction. JSONP works around the restriction by exploiting the fact that scripts can be loaded from any origin — but it has security risks and limitations.

Error Handling

try, catch, finally, and the Error object

Runtime errors in JavaScript are instances of the Error object. The Error object can be thrown with throw new Error(message). You can also throw strings, but using Error preserves stack traces and debugging information. Custom error types can extend Error for more specific handling.

Use try/catch to catch errors: try { riskyOperation(); } catch (error) { console.error(error.message); }. The finally block runs regardless of whether an error occurred — useful for cleanup. A thrown error stops execution of the try block and jumps to the catch block.

JavaScript has six core error constructors: EvalError, InternalError (Firefox only), RangeError, ReferenceError, SyntaxError, TypeError, and URIError. Check which type an error is with instanceof.

Promises have their own error handling: .catch(reason => { ... }) handles rejections. Async functions use try/catch around await. Unhandled promise rejections are silently ignored by default; add a window.addEventListener('unhandledrejection', ...) to catch them.

// Basic try/catch
try {
  throw new Error('Useful message');
} catch (error) {
  console.log('Something went wrong! ' + error.message);
}

// finally
try {
  undefinedFunction();
} catch (error) {
  console.log("An error occurred!", error);
} finally {
  console.log("The code-block has finished");
}

// Error types
try {
  throw new TypeError();
} catch (e) {
  if (e instanceof TypeError) {
    console.log('type error');
  }
}

// Promises
Promise.resolve(5)
  .then(result => {
    throw new Error("I don't like five");
  })
  .catch(error => {
    console.error("Promise rejected: " + error);
  });

// Async/await
async function main() {
  try {
    await Promise.reject(new Error("Invalid something"));
  } catch (error) {
    console.log("Caught error: " + error);
  }
}

// Unhandled rejections
window.addEventListener('unhandledrejection', event => {
  console.log('Unhandled rejection:', event.reason);
});

// Protected function call
function protectedFunction(fn, ...args) {
  try {
    fn.apply(this, args);
  } catch (e) {
    console.log("caught error: " + e.name + " -> " + e.message);
  }
}

Key Ideas

  • try/catch/finally catches errors and ensures cleanup.
  • Use throw new Error(message) for application errors.
  • Error types: TypeError, ReferenceError, RangeError, SyntaxError.
  • Promises reject with errors; catch them with .catch() or try/catch with await.

Global Error Handling in Browsers

Catching errors that escape your try/catch blocks

The window.onerror event handler catches errors that are not caught by try/catch. It is called with the error message, the URL of the script, the line number, the column number, and (in modern browsers) the Error object. This lets you report errors back to the server for logging.

Use window.onerror = function(eventOrMessage, url, lineNumber, colNumber, error) { ... }. Handle the different argument shapes across browsers. Use eventOrMessage as an Error object or a string, depending on the browser. Send the error to the server with an image beacon or a fetch request.

Be careful not to flood the server with errors. Use a flag to report only once, or use rate limiting. Filter out errors from browser extensions and other sources you don't control.

var hasLoggedOnce = false;

window.onerror = function(eventOrMessage, url, lineNumber, colNumber, error) {
  if (hasLoggedOnce || !eventOrMessage) {
    return;
  }
  hasLoggedOnce = true;

  if (typeof eventOrMessage !== 'string') {
    error = eventOrMessage.error;
    url = eventOrMessage.filename || eventOrMessage.fileName;
    lineNumber = eventOrMessage.lineno || eventOrMessage.lineNumber;
    colNumber = eventOrMessage.colno || eventOrMessage.columnNumber;
    eventOrMessage = eventOrMessage.message || eventOrMessage.name || error.message || error.name;
  }

  if (error && error.stack) {
    eventOrMessage = [eventOrMessage, '; Stack: ', error.stack, '.'].join('');
  }

  var jsFile = (/[^/]+\.js/i.exec(url || '') || [])[0] || 'inlineScriptOrDynamicEvalCode',
      stack = [eventOrMessage, ' Occurred in ', jsFile, ':', lineNumber || '?', ':', colNumber || '?'].join('');

  stack = stack.replace(/https?\:\/\/[^/]+/gi, '');
  new Image().src = '/exampleErrorReporting?stack=' + encodeURIComponent(stack);

  if (window.DEBUG_ENVIRONMENT) {
    alert('Client-side script failed: ' + stack);
  }
};

Key Ideas

  • window.onerror catches uncaught errors and lets you report them.
  • The handler receives message, URL, line, column, and (in modern browsers) an Error object.
  • Send errors to the server with an image beacon or a fetch request.
  • Rate-limit error reporting to avoid flooding the server.

Set breakpoints with the debugger; statement, or by clicking line numbers in DevTools. Use console.log, console.table, console.trace, and other console methods to inspect values. Unit Testing JavaScript

Mocha, Chai, Sinon, and basic assertions

Unit testing is the practice of testing individual units of code — usually functions — in isolation. It catches regressions, documents behaviour, and enables confident refactoring. JavaScript has a rich ecosystem of testing tools: Mocha (test runner), Chai (assertion library), Sinon (spies, stubs, mocks), and Proxyquire (dependency injection).

A basic assertion function is easy to write: function assert(outcome, description) { var passFail = outcome ? 'pass' : 'fail'; console.log(passFail, ': ', description); return outcome; }. This is the foundation of any test framework.

For promises, use chai-as-promised and sinon-stub-promise. expect(pingResult).to.be.fulfilled; and expect(pingResult).to.eventually.equal(response);. These make testing async code as natural as testing sync code.

// Basic assertion
function assert(outcome, description) {
  var passFail = outcome ? 'pass' : 'fail';
  console.log(passFail, ': ', description);
  return outcome;
}

function add(num1, num2) {
  return num1 + num2;
}

var result = add(5, 20);
assert(result == 25, 'add(5, 20) should return 25...');

    expect(pingResult).to.be.fulfilled;
  });

    expect(pingResult).to.eventually.equal(response);
  });

Evaluating JavaScript

eval — powerful, dangerous, and almost always the wrong tool

The eval function evaluates a string as JavaScript code. eval('2 + 2') returns 4. The string can be any expression or statement. eval is available in the global scope, and its lexical scope is the local scope unless invoked indirectly.

eval is strongly discouraged. It is slow, it bypasses optimizations, it creates security vulnerabilities, and it makes code harder to reason about. In strict mode, eval does not introduce new variables into the surrounding scope. In some contexts, it is blocked entirely by Content Security Policy.

Use JSON.parse instead of eval for parsing JSON. Use Function constructor or template literals instead of dynamically building code. If you absolutely need eval, ensure the input is fully trusted and sanitized.

// Evaluate a string
eval('2 + 2'); // 4

// Evaluate with variables
var x = 5;
var str = "if (x == 5) {console.log('z is 42'); z = 42;} else z = 0;";
console.log("z is ", eval(str));

// Eval math
var x = 10;
var y = 20;
var a = eval("x * y") + "<br>"; // 200
var b = eval("2 + 2") + "<br>"; // 4
var c = eval("x + 17") + "<br>"; // 27
var res = a + b + c;

// Don't do this — use JSON.parse instead
// eval("(" + resp + ")");

// Better
JSON.parse(resp);

Key Ideas

  • eval evaluates a string as JavaScript code.
  • It is slow, insecure, and bypasses optimizations.
  • Use JSON.parse instead of eval for parsing JSON.
  • Use the Function constructor or template literals instead of dynamic code.

Anti-patterns

Common mistakes that look harmless but cause bugs

Anti-patterns are common solutions that appear to work but are actually flawed. One common example: chaining assignments in a var declaration. var a = b = 0; creates a global b and a local a, because the assignment is right-to-left. var a = (b = 0); — b is global, a is local. This is almost never what you want.

The correct way to chain assignments: var a, b; a = b = 0; — or var a = 0, b = a;. Both make a and b local.

Other anti-patterns include using eval with untrusted data, modifying Object.prototype, using with statements, relying on automatic semicolon insertion, and using == instead of ===. Recognizing these patterns and avoiding them is a mark of professional JavaScript development.

// Anti-pattern: chaining assignments
(function foo() {
  var a = b = 0;
})();
console.log('a: ' + a); // ReferenceError: a is not defined
console.log('b: ' + b); // "b: 0" — b is global!

// Correct way
var a, b;
a = b = 0;

// Or
var a = 0, b = a;

// Another anti-pattern: modifying Object.prototype
// Object.prototype.breakingLibraries = 'foo';

// Another: eval with untrusted data
// eval("(" + resp + ")");

// Another: using == instead of ===
// if (x == null) { ... }

// Another: relying on ASI
// return
// {
//   foo: 'bar'
// };

Key Ideas

  • Chaining assignments in var declarations can create unintended globals.
  • Fix with separate declarations or a single statement: var a = 0, b = a;.
  • Avoid modifying built-in prototypes, using eval with untrusted data, and relying on ASI.
  • Prefer === over ==; use let/const over var.

Performance Tips

Measuring, optimising, and the caution required for both

Performance optimisation is dependent on the JavaScript engine and the specific use case. The fundamental law of performance optimisation is that you must first measure before trying to optimise, and measure again after a presumed optimisation. Use performance.now(), console.time(), or process.hrtime() in Node.js to benchmark your code.

Avoid try/catch in performance-critical functions. Some JavaScript engines don't optimise functions that contain try/catch blocks. Move the slow code into a separate function and call it from inside the try block.

Limit DOM updates. Every DOM update triggers a reflow, which is expensive. Batch changes into a single update: build an HTML string and assign it once, or use a DocumentFragment. Use a memoizer for heavy-computing functions — cache the results of previous calls and return the cached result if the same arguments are passed again.

Prefer local variables to globals. Engines first look for variables within the local scope before extending their search to larger scopes. Prefer integers to floats — engines can represent integers more efficiently. Reuse objects rather than creating new ones, to reduce garbage collection overhead.

// Benchmarking with performance.now()
let startTime, endTime;
function myFunction() {
  // slow code
}
startTime = performance.now();
myFunction();
endTime = performance.now();
console.debug('Elapsed time:', (endTime - startTime));

// Benchmarking with console.time()
console.time("t");
let arr = [];
for (let i = 0; i < 1000000; i++) {
  arr.push(i);
}
console.timeEnd("t");

// Benchmarking with process.hrtime() in Node.js
let start = process.hrtime();
// long execution here
let diff = process.hrtime(start);
console.log(`Operation took ${diff[0] * 1e9 + diff[1]} nanoseconds`);

// Limit DOM updates
var list = document.getElementById("list");
var html = "";
for (var i = 1; i <= 5000; i++) {
  html += `
  • item ${i}
    • `;
}
list.innerHTML = html; // single update

// Or use DocumentFragment

for (var i = 1; i <= 5000; i++) {
  var li = document.createElement("li");
  li.innerHTML = "item " + i;
  fragment.appendChild(li);
}
list.appendChild(fragment);

// Memoizer
function memoize(func) {
  let cache = {};
  function memoized(...args) {
    const argsKey = JSON.stringify(args);
    if (argsKey in cache) {
      console.log(argsKey + ' was/were in cache');
      return cache[argsKey];
    } else {
      cache[argsKey] = func.apply(null, args);
      return cache[argsKey];
    }
  }
  return memoized;
}

  a.x = 0;
  a.y = 0;
  return a;
}

// Prefer local variables

  var local_variable = 0;
  for (var i = 0, li = items.length; i < li; i++) {
    local_variable += items[i];
  }

    Memory Efficiency

    Avoiding leaks and reducing allocations

    Creating true private methods in JavaScript is memory-inefficient. Every time a new instance is created, a copy of the private method is created. For a constructor with a private method and thousands of instances, this wastes significant memory.

    The classic example: function contact(first, last) { var formatPhoneNumber = function(number) { ... }; this.setMobileNumber = function(number) { this.mobile = formatPhoneNumber(number); }; }. Each instance has its own copy of formatPhoneNumber. For a few instances, it doesn't matter. For thousands, it does.

    Use prototype methods for shared behaviour. Contact.prototype.formatPhoneNumber = function(number) { ... }; — all instances share the same function. This is the standard fix. Or use WeakMaps for private data without the per-instance copy. Avoid private methods entirely unless you really need them.

    // Inefficient: private method per instance
function contact(first, last) {
  this.firstName = first;
  this.lastName = last;
  this.mobile;

  var formatPhoneNumber = function(number) {
    // format phone number based on input
  };

  this.setMobileNumber = function(number) {
    this.mobile = formatPhoneNumber(number);
  };
}

var rob = new contact('Rob', 'Sanderson');
var don = new contact('Donald', 'Trump');
var andy = new contact('Andy', 'Whitehall');

// Efficient: shared prototype method
function Contact(first, last) {
  this.firstName = first;
  this.lastName = last;
  this.mobile;
}
Contact.prototype.formatPhoneNumber = function(number) {
  // format phone number based on input
};
Contact.prototype.setMobileNumber = function(number) {
  this.mobile = this.formatPhoneNumber(number);
};

    Key Ideas

    • Private methods created inside the constructor are copied for every instance.
    • Use prototype methods for shared behaviour to save memory.
    • Use WeakMaps for private data without per-instance copies.
    • Avoid private methods entirely unless you really need them.
